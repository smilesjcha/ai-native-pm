## 문서 진행 흐름

제품 개발 과정에서 문서는 다음 순서로 작성된다. 각 단계의 문서는 이전 단계의 문서를 **참조**하되 **복사하지 않는다**.

```
2-Pager (의사결정용 요약)
   ↓  승인
PRD (제품 요구사항 정의서)
   ↓  상세화
   ├── Specs (L2-UX): 와이어프레임, 시나리오, UX 플로우
   ├── HLD/LLD (L2-Tech): 기술 설계
   └── ADR: 아키텍처 결정 기록
          ↓  구현·출시
       Ops (L3): 출시 계획, 품질 리스크
```

---

## 문서별 역할

### 2-Pager (2페이지 요약)

| 항목 | 내용 |
|------|------|
| **언제** | 프로젝트 착수 전, 리더십에게 "할지 말지" 의사결정을 받을 때 |
| **누가** | PM |
| **독자** | 리더십/임원, 의사결정자 |
| **분량** | 1-2페이지 |
| **핵심** | 문제·솔루션·기대효과·필요 리소스를 압축 요약 |
| **위치** | `prd/2pager.md` |

2-Pager가 승인되면 PRD 작성을 시작한다. 승인되지 않으면 PRD를 쓸 필요가 없다.

---

### PRD (L1 — 무엇을, 왜)

| 항목 | 내용 |
|------|------|
| **언제** | 2-Pager 승인 후, 본격 설계·개발 전 |
| **누가** | PM (주도), Design·Eng 협업 |
| **독자** | 전 직군 (PM, Design, Dev, QA, DA, Leadership) |
| **분량** | 10-40페이지 (프로젝트 규모에 따라) |
| **핵심** | Why/What/How 프레임워크 — 문제·솔루션·범위·KPI·일정 |
| **위치** | `prd/PRD.md` (SSOT) |

PRD는 프로젝트의 **SSOT (Single Source of Truth, 단일 진실 원본)**. 모든 하위 문서가 PRD를 참조한다.

---

### Specs (L2-UX — 어떻게 보이는가)

| 항목 | 내용 |
|------|------|
| **언제** | PRD의 §7-§9가 확정된 후 |
| **누가** | Design (주도), PM 협업 |
| **독자** | Design, Frontend Dev, QA |
| **핵심** | 와이어프레임 명세, 시나리오 상세, UX 플로우, 컴포넌트 명세 |
| **위치** | `specs/wireframes/`, `specs/flows/` |

Spec 문서는 Side Document로, 상단에 PRD 참조 원본 섹션을 명시한다.

---

### HLD / LLD (L2-Tech — 어떻게 구현하는가)

| 항목 | 내용 |
|------|------|
| **언제** | PRD의 §9-§10이 확정된 후 |
| **누가** | Engineering (주도), PM 리뷰 |
| **독자** | Backend/Frontend Dev, EM |
| **핵심** | 시스템 아키텍처, 데이터 모델, API 설계, 기술 제약 |
| **위치** | `decisions/hld/HLD.md`, `decisions/lld/LLD.md` |

| 문서 | 추상도 | 내용 |
|------|--------|------|
| **HLD (High-Level Design, 고수준 설계)** | 높음 | 시스템 구성도, 서비스 간 통신, 데이터 흐름 |
| **LLD (Low-Level Design, 상세 설계)** | 낮음 | 클래스 설계, DB 스키마, API 인터페이스 상세 |

---

### ADR (아키텍처 결정 기록)

| 항목 | 내용 |
|------|------|
| **언제** | 기술적 선택이 필요할 때 (여러 대안 중 하나를 결정) |
| **누가** | Engineering (주도), PM·EM 협의 |
| **독자** | Engineering, 미래의 팀원 |
| **핵심** | 결정 배경, 검토한 대안들, 선택 이유, 트레이드오프 (Trade-off, 상충 관계) |
| **위치** | `decisions/adr/ADR-NNN-name.md` |

---

### Ops (L3 — 어떻게 출시·운영하는가)

| 항목 | 내용 |
|------|------|
| **언제** | 개발 중~출시 직전 |
| **누가** | PM (주도), QA·Eng 협업 |
| **독자** | PM, QA, Ops |
| **핵심** | 출시 체크리스트, 롤백 계획, 품질 리스크, WBS (Work Breakdown Structure, 작업 분해 구조) |
| **위치** | `ops/quality-risk.md`, `ops/rollout-wbs.md` |

## 의사결정 트리: 어떤 문서를 언제 쓸까?

```
"프로젝트를 시작하려는데, 어떤 문서부터?"
   ↓
아직 리더십 승인 전인가?
   ├── 예 → 2-Pager 작성
   └── 아니오 (승인됨) → PRD 작성
                           ↓
                    디자인 착수 단계인가?
                       ├── 예 → Specs 작성 (PRD §7-§9 참조)
                       └── 아니오
                              ↓
                    기술 설계 단계인가?
                       ├── 예 → HLD 작성 (PRD §9-§10 참조)
                       │        기술 결정이 필요하면 → ADR 작성
                       └── 아니오
                              ↓
                    출시 준비 단계인가?
                       └── 예 → Ops 문서 작성
```

## 문서 간 참조 원칙

1. **아래 → 위 참조**: 하위 계층 문서는 상위 문서의 특정 섹션을 Side Document 헤더로 참조한다
2. **위 → 아래 링크**: 상위 문서는 하위 문서를 링크로 연결한다 (복사 금지)
3. **같은 계층 독립**: 같은 계층의 문서끼리는 직접 참조하지 않는다 (PRD를 경유)
4. **_index.md가 지도**: 프로젝트의 모든 문서 관계는 `_index.md`에서 한눈에 볼 수 있다
