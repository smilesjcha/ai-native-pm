# 이해관계자 정렬 플레이북 — 디자이너·개발자·리더십을 이해시키는 법

> Status: Active
> Document Type: Guide
> Last Updated: 2026-06-26
> Last Author: PM 차성재 with Claude Opus 4.8
> Owner: PM 차성재
> 연계: [PRD 작성 플레이북](./prd-authoring-playbook.md) · [3관점 평가 기준](../evaluation/)

## 결론부터 (BLUF)

> **같은 PRD라도 청중마다 다른 질문을 한다.** 디자이너는 "그릴 수 있나?", 개발자는 "만들 수 있나?", 리더십은 "투자할 가치가 있나?"를 묻는다.
> 정렬의 기술은 **하나의 SSOT(PRD)를 청중별 ‘렌즈’로 다르게 보여주는 것** — 산출물(시안·프로토타입·데모 영상·데이터)을 청중이 가장 빠르게 ‘이해’하는 형태로 프레이밍한다.
> 합의의 증거는 [3관점 평가](../evaluation/)를 모두 통과(각 20점+)한 **Approved**다.

---

## 1. 왜 ‘다각적 정렬’인가

한 PRD를 던지고 "읽어보세요"는 실패한다. 청중은 자기 질문에 대한 답이 **첫 30초**에 안 보이면 신뢰를 닫는다.

| 청중 | 한 문장 질문 | 닫히는 순간 |
|------|--------------|-------------|
| 디자이너 | "이걸로 화면을 그릴 수 있나?" | 플로우·예외·컴포넌트가 모호할 때 |
| 개발자/EM | "주어진 기간·리소스로 만들 수 있나?" | 범위·로깅·NFR이 비어 있을 때 |
| 리더십 | "이 프로젝트에 투자할 가치가 있나?" | 비즈니스 임팩트·지표가 추상적일 때 |

→ **해법: 청중별 진입점(렌즈)을 PRD 안에 미리 만든다.** (두괄식·시안·데모·지표가 각 렌즈)

## 2. 이해관계자별 정렬 카드

### 2-1. 디자이너 — "그릴 수 있게 해줘"

| 항목 | 내용 |
|------|------|
| **핵심 질문** | 이 PRD만으로 와이어프레임을 그릴 수 있는가? |
| **가장 신경 쓰는 것** | 시나리오 완전성(MECE), User Flow, 예외/빈 상태, 에이전트 대화·카피, 컴포넌트 |
| **무엇을 보여주면 이해하나** | **코드 기반 시안**(Home/SRP/PLP/PDP) · User Flow 보드 · 디자인 시스템 토큰 · 에이전트 카피 가이드 |
| **설득 프레이밍** | "여기까지 정의했으니, 당신은 ‘질문 없이’ 시안을 디벨롭하면 된다" |
| **PRD 어느 섹션** | §Core Scenarios(User Flow) · §Entry Surface & UX · §시안(§8A) · §Functional Spec |
| **자주 나오는 반론 → 대응** | "엣지케이스가 없다" → 빈/오류/로딩 상태를 시나리오에 명시 / "톤이 모호" → 에이전트 카피 예시·금칙어를 정책에 |
| **합의 게이트(yes의 모습)** | 디자인 관점 [eval-design](../evaluation/eval-design.md) 20점+ · "추가 질문 없이 시안 착수 가능" |

### 2-2. 개발자 / EM — "만들 수 있게 해줘"

| 항목 | 내용 |
|------|------|
| **핵심 질문** | 이 범위를 주어진 기간·리소스로 만들 수 있는가? |
| **가장 신경 쓰는 것** | 측정 가능한 지표·로깅, 범위(In/Out), NFR, 데이터/연동, 에이전트 정책, 공수 |
| **무엇을 보여주면 이해하나** | **동작 프로토타입(=살아있는 명세)** · 이벤트 로깅 설계 · mock 데이터 스키마 · 가드레일 · NFR 표 |
| **설득 프레이밍** | "무엇을 만들지·측정할지·하지 말지가 다 적혀 있다. 추정만 하면 된다" |
| **PRD 어느 섹션** | §Functional Spec · §Success Metrics(로깅) · §NFR · §AI Model & Agent Policy · §Scope |
| **자주 나오는 반론 → 대응** | "범위가 무한" → Out of Scope·1차 지면(SRP·PLP·PDP) 명시 / "측정 불가" → Baseline→Target→이벤트 3종 세트 / "AI 신뢰?" → 가드레일·폴백 정의 |
| **합의 게이트** | EM 관점 [eval-engineering](../evaluation/eval-engineering.md) 20점+ · "T-사이징 가능 + 릴리즈 게이트 합의" |

### 2-3. 리더십 — "투자할 가치를 보여줘"

| 항목 | 내용 |
|------|------|
| **핵심 질문** | 이 프로젝트에 투자할 가치가 있는가? |
| **가장 신경 쓰는 것** | 전략 정합성, 비즈니스 임팩트·지표(ROI), 차별점, 리스크, Go/No-Go |
| **무엇을 보여주면 이해하나** | **2-Pager/BLUF** · **데모 영상**(감으로 ‘된다’) · 성공 지표(Baseline→Target) · 벤치마크 차별점 · 코호트·퍼널 임팩트 |
| **설득 프레이밍** | "이 지표를 이만큼 움직인다. 근거는 데이터와 동작 데모다" (30초 안에) |
| **PRD 어느 섹션** | 결론부터(BLUF) · §Success Metrics · §벤치마크 비교 · §Milestones · 2-Pager |
| **자주 나오는 반론 → 대응** | "왜 지금?" → 전략·OKR 연결 / "효과 의심" → mock 코호트·퍼널 + 데모 / "리스크" → 가드레일·롤백·단계적 출시 |
| **합의 게이트** | 리더십 관점 [eval-leadership](../evaluation/eval-leadership.md) 20점+ · "착수 승인 + 게이트 동의" |

## 3. 산출물 × 청중 매트릭스 (무엇이 누구를 설득하나)

> 같은 산출물도 청중마다 ‘증명하는 것’이 다르다. 미팅 전, 어떤 산출물을 누구에게 들이밀지 정한다.

| 산출물 | 디자이너에게 | 개발자/EM에게 | 리더십에게 |
|--------|--------------|----------------|------------|
| **2-Pager / BLUF** | 맥락 | 범위 감 | ◎ 의사결정(30초) |
| **PRD 본문** | ◎ 화면 범위·플로우 | ◎ 명세·범위·NFR | 핵심 지표만 |
| **코드 기반 시안** | ◎ 시안 착수 | 화면 수·상태 | 완성도 신뢰 |
| **동작 프로토타입** | UX 검증 | ◎ 살아있는 명세 | ‘된다’ 체감 |
| **데모 영상(MP4)** | UX 흐름 | 스코프 윤곽 | ◎ 감정적 확신 |
| **코호트·퍼널 분석** | — | ◎ 로깅 설계 | ◎ 임팩트·근거 |
| **지면별 Agent 매트릭스** | 화면 우선순위 | 1차 범위 | 투자 범위 |

◎ = 그 청중에게 가장 강한 무기

---

## 4. 정렬 미팅 운영 (실전)

> 한 번에 다 모으지 말고, **청중별 진입 순서·시간·무기**를 다르게.

1. **리더십 (5분)** — BLUF 1장 + 데모 영상 30초 + 지표 1장 → Go 사인.
2. **디자이너 (비동기/30분)** — 시안·User Flow 공유 → 코멘트(6카테고리) → 시안 착수.
3. **개발자/EM (30분)** — 프로토타입 시연 + 명세·로깅·정책 → T-사이징·게이트 합의.
4. **종합** — 3관점 평가 점수표로 Approved 판정 → 일정 확정.

> 도구 연계: 비동기 리뷰는 [AI Doc Feedback Loop](../../projects/26Q2_AI-Doc-Feedback-Loop/) (6카테고리 댓글 → AI 개선안)로 한 곳에서.

## 5. Shopping Mate 적용 예시 (한 PRD, 세 청중)

| 청중 | 들이미는 것 | 한 줄 멘트 |
|------|-------------|-----------|
| 리더십 | BLUF + 데모 영상 + "상세→장바구니 CVR 22→30%" | "이 한 지표를 8%p 올립니다. 데모로 보세요." |
| 디자이너 | Home/SRP/PLP/PDP 시안 + User Flow 보드 | "지면별 Agent 위치까지 잡았어요. 시안 디벨롭만 하면 됩니다." |
| 개발자/EM | 프로토타입 + 이벤트 로깅 + 가드레일 + 1차 범위(SRP·PLP·PDP) | "범위·측정·정책 다 있어요. 추정만 주세요." |
