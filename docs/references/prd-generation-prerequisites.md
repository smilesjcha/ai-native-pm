## 문서 목적

AI로 PRD를 생성하기 전에 **어떤 준비물이 갖춰져야 하는지**를 정의한다.
"프롬프트 품질 = PRD 품질"이라는 전제 하에, AI에게 넘기기 전 PM이 확보해야 할 맥락·자료·환경을 카테고리별로 정리한다.

---

## 1. 비즈니스 맥락 (Business Context)

PRD의 "왜 만드는가"를 AI가 이해하기 위한 필수 입력물.

| 준비물 | 설명 | 확보 방법 |
|--------|------|----------|
| 비즈니스 목표 / OKR | 이번 분기 또는 해당 이니셔티브의 상위 목표 | OKR 문서, 분기 계획서 |
| 해결할 사용자 문제 | 구체적인 Pain Point | 사용자 인터뷰, VOC 데이터, CS 로그 |
| 성공 지표 (NSM / KPI) | 어떤 숫자가 움직이면 성공인지 | 데이터팀 협의, 기존 대시보드 |
| 경쟁사·시장 벤치마크 | 유사 기능의 시장 현황 | 경쟁사 분석, 시장 리서치 |
| 비즈니스 제약 조건 | 일정, 예산, 법적·정책적 제약 | 유관 부서 확인 |

**AI에게 잘 되는 영역**: 경쟁사 분석 초안, 시장 트렌드 요약
**PM이 직접 써야 하는 영역**: 우선순위 판단 근거, Trade-off 결정, OKR 연결

---

## 2. 사용자·고객 리서치 (User & Customer Research)

PRD의 사용자 스토리, 시나리오, 페르소나를 뒷받침하는 근거 자료.

| 준비물 | 설명 | 확보 방법 |
|--------|------|----------|
| 사용자 세그먼트 정의 | 대상 사용자 그룹과 특성 | 사용자 데이터 분석, 마케팅팀 협의 |
| 사용자 여정 맵 (AS-IS) | 현재 사용자 경험 흐름 | UX 리서치, 행동 로그 분석 |
| VOC / CS 데이터 | 사용자 불만·요청 패턴 | CS팀 로그, 앱 리뷰, 설문 |
| 사용자 인터뷰 요약 | 정성 리서치 핵심 인사이트 | 인터뷰 노트, 녹취 요약 |
| 정량 데이터 | 관련 지표 현황 (트래픽, 전환율, 이탈률 등) | 데이터 대시보드 |

---

## 3. 기술·시스템 현황 (Technical Context)

PRD의 기술 제약사항과 비기능 요구사항을 정의하기 위한 입력물.

| 준비물 | 설명 | 확보 방법 |
|--------|------|----------|
| 현재 시스템 아키텍처 | AS-IS 시스템 구성도 | 엔지니어링팀, 기존 HLD |
| API / 서비스 의존성 | 연동 필요한 외부·내부 서비스 | 기술 문서, 엔지니어링 협의 |
| 기술 제약 조건 | 사용 불가 기술, 레거시 제약 | EM 협의 |
| 인프라 예산 | 서버·DB·API 비용 한도 | 재무팀, EM 협의 |

---

## 4. 정책·규제 (Policy & Compliance)

서비스 정책, 가드레일, 법적 요구사항을 PRD에 반영하기 위한 입력물.

| 준비물 | 설명 | 확보 방법 |
|--------|------|----------|
| 관련 서비스 정책 | 노출 정책, 정산 정책 등 | 정책팀, 기존 정책 문서 |
| 개인정보 처리 기준 | PII 수집·저장·삭제 규칙 | 법무팀, DPO |
| 규제 요구사항 | 전자상거래법, 표시광고법 등 | 법무팀 |
| 접근성 기준 | WCAG 레벨, 지원 디바이스 | 디자인팀, QA |

---

## 5. 협업 환경 (Collaboration)

PRD 작성·리뷰 프로세스를 원활히 하기 위한 환경 확인.

| 준비물 | 설명 | 확인 사항 |
|--------|------|----------|
| 팀 구성 확정 | PM, Design, Dev, QA 담당자 | 인사·조직 확인 |
| 리뷰 프로세스 합의 | 리뷰 사이클, 승인자 | 팀 리드 합의 |
| 도메인 컨텍스트 문서 | `context/` 폴더에 관련 도메인 지식 저장 | 유관 부서 문서 수집 |
| 디자인 리소스 | 디자인 시스템, 컴포넌트 목록 | 디자인팀 공유 |

## 체크리스트 (작성 전 최종 확인)

### 필수 (이것 없이는 PRD 생성 불가)

- [ ] 비즈니스 목표 / OKR이 명확한가?
- [ ] 해결할 사용자 문제가 데이터로 뒷받침되는가?
- [ ] 성공 지표(KPI)가 정의되어 있는가?
- [ ] 일정·예산 제약이 파악되어 있는가?
- [ ] 팀 구성이 확정되어 있는가?

### 권장 (있으면 PRD 품질이 높아짐)

- [ ] 사용자 리서치(VOC, 인터뷰, 데이터)가 있는가?
- [ ] 현재 시스템 아키텍처를 이해하고 있는가?
- [ ] 관련 정책·규제를 확인했는가?
- [ ] 경쟁사·시장 벤치마크를 수행했는가?
- [ ] `context/` 폴더에 도메인 지식을 저장했는가?
