## 핵심 질문

> **"이 PRD만으로 와이어프레임을 그릴 수 있는가?"**

디자이너는 PRD를 읽고 화면을 설계한다. PRD에 시나리오, 화면 흐름, 인터랙션, 예외 처리가 충분히 정의되지 않으면, 디자이너가 추측에 의존하거나 PM에게 반복 질문해야 한다.

---

## 평가 체계

- **6개 항목**, 각 1-5점 (총 30점 만점)
- **통과 기준**: 총점 20점 이상 **+** 각 항목이 개별 최소 점수 이상
- **가중치**: 시나리오 완전성과 컴포넌트 수준 명세에 1.5배 가중

---

## 평가 항목

### 1. 시나리오 완전성 (Scenario Completeness) — 가중치 x1.5

**평가 질문**: 사용자의 핵심 사용 흐름이 MECE (Mutually Exclusive Collectively Exhaustive, 상호 배타적·전체 포괄적)하게 정의되어, 디자인해야 할 화면의 범위를 알 수 있는가?

| 점수 | 기준 |
|------|------|
| **1점** | 시나리오가 없다. 기능 목록만 있고, 사용자가 어떤 흐름으로 쓰는지 알 수 없다 |
| **2점** | 메인 시나리오(Happy Path) 1-2개만 있다. 분기나 변형이 고려되지 않았다 |
| **3점** | 주요 시나리오가 3개 이상이고, 각 시나리오에 트리거·단계·결과가 있다 |
| **4점** (최소 통과) | 3점 조건 + 시나리오 간 관계(분기·합류)가 명확하고, P0/P1 우선순위가 있다 |
| **5점** | 4점 조건 + 에지 케이스(Edge Case, 경계 사례) 시나리오와 에러 시나리오까지 포함된다 |

---

### 2. UI/UX 플로우 상세도 (Flow Detail) — 가중치 x1.0

**평가 질문**: 진입점(Entry Point)에서 최종 결과까지의 화면 전환 흐름이 명확한가?

| 점수 | 기준 |
|------|------|
| **1점** | 화면 흐름에 대한 언급이 없다 |
| **2점** | 시작과 끝만 있고, 중간 단계가 생략되어 있다 |
| **3점** (최소 통과) | 진입점 → 주요 화면 → 결과 화면의 전환 흐름이 단계별로 서술된다 |
| **4점** | 3점 조건 + 각 화면에서 사용자가 취할 수 있는 액션(탭, 스크롤, 입력 등)이 명시된다 |
| **5점** | 4점 조건 + 뒤로가기, 중간 이탈, 재진입 시의 상태 처리까지 정의된다 |

---

### 3. 가드레일·예외 처리 (Guardrails & Edge Cases) — 가중치 x1.0

**평가 질문**: "잘못되었을 때 어떻게 되는가"가 정의되어 있어 에러 상태를 디자인할 수 있는가?

| 점수 | 기준 |
|------|------|
| **1점** | 예외 상황이나 에러 케이스에 대한 언급이 전혀 없다 |
| **2점** | "에러 시 적절히 처리한다" 수준의 추상적 서술만 있다 |
| **3점** (최소 통과) | 주요 에러 유형(네트워크 오류, 빈 결과, 권한 부족 등)이 나열되어 있다 |
| **4점** | 3점 조건 + 각 에러에 대한 폴백(Fallback, 대안 동작)이 구체적으로 정의된다 |
| **5점** | 4점 조건 + 금지 행위(하면 안 되는 것), 입력 제한, 안전 장치까지 정책으로 명시된다 |

---

### 4. 컴포넌트 수준 명세 (Component Specs) — 가중치 x1.5

**평가 질문**: 화면 내 개별 요소(버튼, 카드, 인풋, 모달 등)의 상태와 인터랙션이 정의되어 있는가?

| 점수 | 기준 |
|------|------|
| **1점** | 화면에 어떤 요소가 있는지 전혀 모른다. "검색 기능"만 있고 구체적 UI가 없다 |
| **2점** | 화면에 들어갈 요소가 나열되지만, 상태(활성/비활성/로딩/에러)가 없다 |
| **3점** (최소 통과) | 주요 컴포넌트의 기본 상태와 인터랙션(클릭, 입력 시 동작)이 서술된다 |
| **4점** | 3점 조건 + 컴포넌트의 다중 상태(비어있을 때, 로딩 중, 에러, 성공)가 정의된다 |
| **5점** | 4점 조건 + 기존 디자인 시스템 컴포넌트 매핑 또는 새로운 컴포넌트 필요 여부가 명시된다 |

---

### 5. 단계별 기능 정의 (Phased Feature Definition) — 가중치 x1.0

**평가 질문**: P0 (최소 출시 범위)와 P1 (다음 단계)이 구분되어, 디자이너가 어디에 집중해야 하는지 아는가?

| 점수 | 기준 |
|------|------|
| **1점** | 기능에 우선순위 구분이 없다. 모든 것이 동일한 무게로 나열된다 |
| **2점** | P0/P1이 표시되어 있으나, P0만으로 완성된 사용자 경험이 되는지 불분명하다 |
| **3점** (최소 통과) | P0 기능만으로 핵심 시나리오가 완성되며, P1은 확장 기능으로 명확히 분리된다 |
| **4점** | 3점 조건 + 분기별(Q2/Q3/Q4) 진화 방향이 있어 장기 디자인 방향을 잡을 수 있다 |
| **5점** | 4점 조건 + P0에서 P1으로 넘어갈 때 UI가 어떻게 확장/변형되는지 서술된다 |

---

### 6. 접근성·반응형 고려 (Accessibility & Responsive) — 가중치 x1.0

**평가 질문**: 다양한 디바이스와 접근성(Accessibility) 요구사항이 고려되어 있는가?

| 점수 | 기준 |
|------|------|
| **1점** | 디바이스나 접근성에 대한 언급이 전혀 없다 |
| **2점** (최소 통과) | 대상 디바이스/플랫폼(모바일 웹, 앱, 데스크톱 등)이 명시되어 있다 |
| **3점** | 2점 조건 + 최소 지원 화면 크기 또는 반응형 고려사항이 있다 |
| **4점** | 3점 조건 + 웹 접근성 기준(WCAG 수준)이 명시되어 있다 |
| **5점** | 4점 조건 + 다크모드, 고대비 모드, 스크린리더 대응 등 구체적 접근성 요구가 있다 |

## Claude 평가 프롬프트

아래 프롬프트를 복사하여 Claude에게 PRD 평가를 요청할 수 있다.

````
당신은 IT 서비스 회사의 시니어 프로덕트 디자이너(Lead/Principal급)입니다.
아래 PRD를 읽고, **디자이너 관점**에서 6개 항목을 평가해주세요.

핵심 질문: "이 PRD만으로 와이어프레임을 그릴 수 있는가?"

## 평가 항목 (각 1-5점)

1. **시나리오 완전성** (가중치 x1.5, 최소 ≥4)
   - 핵심 사용 흐름이 MECE하게 정의되어 있는가?
   - 5점: Happy Path + 에지 케이스 + 에러 시나리오까지 포함

2. **UI/UX 플로우 상세도** (가중치 x1.0, 최소 ≥3)
   - 진입점에서 결과까지 화면 전환 단계가 명확한가?
   - 5점: 뒤로가기, 중간 이탈, 재진입 시 상태까지 정의

3. **가드레일·예외 처리** (가중치 x1.0, 최소 ≥3)
   - 에러·빈 상태·금지 행위에 대한 폴백이 정의되어 있는가?
   - 5점: 에러 유형별 폴백 + 금지 행위 + 입력 제한까지 정책화

4. **컴포넌트 수준 명세** (가중치 x1.5, 최소 ≥3)
   - 화면 내 요소(버튼, 카드, 인풋 등)의 상태와 인터랙션이 정의되어 있는가?
   - 5점: 다중 상태(빈/로딩/에러/성공) + 디자인 시스템 매핑

5. **단계별 기능 정의** (가중치 x1.0, 최소 ≥3)
   - P0/P1이 구분되고, P0만으로 완성된 사용자 경험이 되는가?
   - 5점: 분기별 확장 방향 + P0→P1 UI 변형 서술

6. **접근성·반응형 고려** (가중치 x1.0, 최소 ≥2)
   - 대상 디바이스/플랫폼과 접근성 요구사항이 명시되어 있는가?
   - 5점: 다크모드, 고대비, 스크린리더 대응까지 구체적

## 출력 형식

각 항목에 대해:
- **점수**: N/5
- **근거**: 점수를 준 구체적 이유 (PRD의 어떤 부분이 충분하거나 부족한지)
- **디자이너가 추가로 필요한 것**: (3점 미만일 때) 와이어프레임 착수 전에 PM에게 확인받아야 할 사항

마지막에 **총평**과 **Pass/Fail** 판정을 내려주세요.
(통과 기준: 가중 합계 23/35 이상 + 개별 최소 점수 충족)
````
