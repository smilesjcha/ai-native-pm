## 핵심 질문

> **"이 범위를 주어진 기간과 리소스로 만들 수 있는가?"**

EM (Engineering Manager)은 기술 리소스의 배분과 실행 가능성을 판단하는 역할이다. PRD를 읽고 "이 범위가 현실적인지, 비용은 얼마나 드는지, 성공 여부를 어떻게 측정하는지"를 판단할 수 있어야 한다.

---

## 평가 체계

- **6개 항목**, 각 1-5점 (총 30점 만점)
- **통과 기준**: 총점 20점 이상 **+** 각 항목이 개별 최소 점수 이상
- **가중치**: 성공 지표 측정 가능성과 P0/P1 스코프 실현 가능성에 1.5배 가중

---

## 평가 항목

### 1. 성공 지표 측정 가능성 (Metrics Measurability) — 가중치 x1.5

**평가 질문**: 정의된 성공 지표를 실제로 측정할 수 있는 인프라와 방법이 존재하는가?

| 점수 | 기준 |
|------|------|
| **1점** | 성공 지표가 없거나, "만족도 향상" 같은 측정 불가능한 지표만 있다 |
| **2점** | 지표가 있으나 현재 측정 인프라가 없고, 구축 계획도 없다 |
| **3점** | 지표에 Baseline (현재값)과 Target (목표값)이 있으나, 측정 방법이 불분명하다 |
| **4점** (최소 통과) | 지표별 측정 방법(대시보드, 로그, A/B 테스트 프레임워크)이 명시되고, 기존 인프라로 측정 가능하거나 구축 비용이 포함되어 있다 |
| **5점** | 4점 조건 + 릴리즈 게이트(Go/No-Go 기준), 모니터링 알림, 롤백 판단 지표까지 정의되어 있다 |

### 2. 비용 추정 (Cost Estimation) — 가중치 x1.0

**평가 질문**: 인프라·AI API·운영 비용이 합리적으로 추정되어 있는가?

| 점수 | 기준 |
|------|------|
| **1점** | 비용에 대한 언급이 전혀 없다 |
| **2점** | "비용이 발생할 수 있다" 수준의 정성적 서술만 있다 |
| **3점** (최소 통과) | 주요 비용 항목(서버, DB, CDN, AI API 등)이 나열되고, 개략적 월 비용이 추정된다 |
| **4점** | 3점 조건 + 트래픽 증가 시나리오(x2, x5, x10)에 따른 비용 변화가 추정된다 |
| **5점** | 4점 조건 + 비용 최적화 방안과 비용 상한(Budget Cap, 예산 한도)이 명시된다 |

**비용 추정 항목 참고표**:

| 비용 항목 | 추정 방법 | 예시 |
|-----------|----------|------|
| **서버/인프라** | 서버 스펙 × 대수 × 월 단가 | AWS m5.xlarge × 3대 = 월 $500 |
| **데이터베이스** | 스토리지 + IOPS (Input/Output Per Second) 기준 | RDS r5.large + 100GB = 월 $300 |
| **AI API 비용** | 건당 평균 토큰 × 일 호출량 × 30일 | GPT-4.1-mini: 1K 토큰 × 10만건/일 × 30일 = 월 $1,500 |
| **CDN/트래픽** | 예상 전송량 기반 | CloudFront 1TB/월 = $85 |
| **모니터링/로그** | 로그 볼륨 기반 | Datadog: 월 $200 |

### 3. 공수 산정 (Workforce: MM/MD by Grade) — 가중치 x1.0

**평가 질문**: 직군·등급별 필요 인력과 투입 기간이 추정되어 있는가?

| 점수 | 기준 |
|------|------|
| **1점** | 인력에 대한 언급이 없다 |
| **2점** | "개발자 2명이 필요하다" 수준의 대략적 서술만 있다 |
| **3점** (최소 통과) | 직군별(Backend, Frontend, Design, QA 등) 인원과 투입 기간이 MM (Man-Month, 인월) 또는 MD (Man-Day, 인일) 단위로 추정된다 |
| **4점** | 3점 조건 + 엔지니어 등급(시니어/미드/주니어)별 배분이 있고, 병렬 가능 여부가 고려된다 |
| **5점** | 4점 조건 + 의존성(Dependency) 때문에 병렬 불가능한 구간이 식별되고, 크리티컬 패스(Critical Path, 임계 경로)가 명시된다 |

**공수 산정 기본 용어**:

| 용어 | 의미 | 환산 |
|------|------|------|
| **MD (Man-Day, 인일)** | 1명이 1일(8시간) 일하는 분량 | 기본 단위 |
| **MM (Man-Month, 인월)** | 1명이 1개월(약 20영업일) 일하는 분량 | 1MM = 20MD |
| **FTE (Full-Time Equivalent, 전일 환산 인원)** | 프로젝트에 전일 투입되는 인원 수 | 1FTE = 월 20MD 투입 |

**엔지니어 등급별 참고 기준**:

| 등급 | 경력 | 독립 수행 범위 | 일반적 일 단가 범위 (참고) |
|------|------|--------------|-------------------------|
| **시니어 (Senior)** | 7년+ | 아키텍처 설계, 기술 의사결정, 코드 리뷰 리드 | 높음 |
| **미드 (Mid-Level)** | 3-7년 | 피처 단위 독립 개발, 일부 기술 의사결정 | 중간 |
| **주니어 (Junior)** | 0-3년 | 명확한 태스크 단위 개발, 시니어 가이드 필요 | 기본 |

**공수 산정 예시 테이블**:

| 직군 | 등급 | 인원 | P0 투입 (MD) | P1 투입 (MD) | 합계 (MD) | MM 환산 |
|------|------|------|-------------|-------------|----------|---------|
| Backend | 시니어 | 1 | 40 | 20 | 60 | 3.0 |
| Backend | 미드 | 1 | 60 | 30 | 90 | 4.5 |
| Frontend | 미드 | 1 | 40 | 20 | 60 | 3.0 |
| Design | 시니어 | 1 | 20 | 10 | 30 | 1.5 |
| QA | 미드 | 1 | 15 | 10 | 25 | 1.25 |
| **합계** | | **5** | **175** | **90** | **265** | **13.25** |

### 4. P0/P1 스코프 실현 가능성 (Scope Feasibility) — 가중치 x1.5

**평가 질문**: P0 범위가 주어진 일정과 인력으로 완수 가능한가? P0 범위를 조정할 수 있는 여지가 있는가?

| 점수 | 기준 |
|------|------|
| **1점** | P0/P1 구분이 없다. 전체 범위가 하나의 덩어리로 되어 있다 |
| **2점** | P0/P1이 구분되지만, P0 범위가 일정 대비 비현실적으로 크다 |
| **3점** (최소 통과) | P0 범위가 주어진 일정·인력으로 달성 가능한 수준이며, P1은 명확히 분리되어 있다 |
| **4점** | 3점 조건 + P0 범위를 줄여야 할 때의 "최소 MVP (Minimum Viable Product, 최소 기능 제품)" 기준이 제시된다 |
| **5점** | 4점 조건 + 기술적 의존성(외부 API, 다른 팀 작업)이 식별되고, 의존성 지연 시 대안이 있다 |

**P0 스코프 조정 프레임워크**:

일정이 부족할 때 PM과 EM이 함께 판단하는 기준:

| 상황 | 조정 방법 | 판단 기준 |
|------|----------|----------|
| P0 범위가 일정 대비 120% 이상 | **기능 축소**: P0에서 일부를 P1으로 이동 | 핵심 시나리오를 완성하는 데 필수적인가? |
| 인력이 부족한 경우 | **인력 추가** 또는 **일정 연장** | 추가 인력의 온보딩 비용 vs 일정 연장의 기회비용 |
| 기술 의존성 지연 | **임시 대안(Workaround) 적용** | 임시 대안의 기술 부채(Tech Debt) 수용 가능한가? |
| 품질 리스크 | **출시 범위 축소 + 모니터링 강화** | 릴리즈 게이트를 충족하는 최소 범위는? |

### 5. ROI 산출 프레임워크 (ROI Framework) — 가중치 x1.0

**평가 질문**: 투입 비용과 기대 효과가 수치화되어, ROI를 계산할 수 있는가?

| 점수 | 기준 |
|------|------|
| **1점** | 비용이나 효과에 대한 정량적 언급이 전혀 없다 |
| **2점** | 기대 효과만 추상적으로 서술되고, 투입 비용은 없다 |
| **3점** (최소 통과) | 투입 비용(인력+인프라)과 기대 효과(매출/비용절감)가 둘 다 개략 수치로 추정된다 |
| **4점** | 3점 조건 + ROI 또는 Payback Period (투자 회수 기간)가 계산되어 있다 |
| **5점** | 4점 조건 + 낙관/비관 시나리오별 ROI가 있고, 손익분기점(Break-Even Point)이 명시된다 |

**ROI 계산 템플릿**:

```
[투입 비용 (A)]
├── 인력 비용: [직군별 인원] × [등급별 월 단가] × [기간(월)]
├── 인프라 비용: [서버/DB/CDN 등 월 비용] × [기간(월)]
├── AI API 비용: [건당 평균 비용] × [예상 일 호출량] × [30일] × [기간(월)]
└── 기타: [라이선스, 외부 서비스 등]

총 투입 비용 = A

[기대 효과 (B)] — 연 환산
├── 매출 증분: [전환율 개선] × [객단가] × [트래픽]
├── 비용 절감: [자동화로 절감되는 인건비/운영비]
└── 생산성 향상: [시간 절감] × [관련 인력 수]

총 기대 효과 (연) = B

ROI = (B - A) / A × 100%
Payback Period (투자 회수 기간) = A / (B ÷ 12) 개월
```

### 6. 비기능 요구사항 충분성 (NFR Sufficiency) — 가중치 x1.0

**평가 질문**: 성능, 보안, 확장성 등 비기능 요구사항이 구체적 수치로 정의되어, 아키텍처 설계의 기준이 되는가?

| 점수 | 기준 |
|------|------|
| **1점** | 비기능 요구사항이 전혀 없다 |
| **2점** | "빠르게 동작해야 한다" 수준의 추상적 서술만 있다 |
| **3점** (최소 통과) | 응답 시간(Latency), 가용성(Availability) 등 핵심 NFR이 수치로 정의된다 |
| **4점** | 3점 조건 + 부하 테스트 기준(동시 접속, TPS), 보안 기준(OWASP 등)이 포함된다 |
| **5점** | 4점 조건 + 트래픽 증가(x10, x50)에 대한 확장성(Scalability) 계획이 있다 |

## Claude 평가 프롬프트

아래 프롬프트를 복사하여 Claude에게 PRD 평가를 요청할 수 있다.

````
당신은 IT 서비스 회사의 시니어 Engineering Manager (EM, 개발 리드급)입니다.
아래 PRD를 읽고, **Engineering Manager 관점**에서 6개 항목을 평가해주세요.

핵심 질문: "이 범위를 주어진 기간과 리소스로 만들 수 있는가?"

## 평가 항목 (각 1-5점)

1. **성공 지표 측정 가능성** (가중치 x1.5, 최소 ≥4)
   - 지표별 측정 방법(대시보드, 로그, A/B 프레임워크)이 명시되어 있는가?
   - 5점: 릴리즈 게이트 + 모니터링 알림 + 롤백 판단 지표까지 정의

2. **비용 추정** (가중치 x1.0, 최소 ≥3)
   - 인프라·AI API·운영 비용이 항목별로 추정되어 있는가?
   - 5점: 트래픽 증가 시나리오별 비용 변화 + 비용 최적화 방안

3. **공수 산정 (MM/MD)** (가중치 x1.0, 최소 ≥3)
   - 직군·등급(시니어/미드/주니어)별 인원과 투입 기간이 추정되어 있는가?
   - 5점: 의존성으로 인한 병렬 불가 구간 식별 + 크리티컬 패스 명시

4. **P0/P1 스코프 실현 가능성** (가중치 x1.5, 최소 ≥3)
   - P0 범위가 일정·인력 대비 현실적인가? 축소 시 최소 MVP 기준이 있는가?
   - 5점: 기술 의존성 식별 + 지연 시 대안 + 스코프 조정 기준

5. **ROI 산출 프레임워크** (가중치 x1.0, 최소 ≥3)
   - 투입 비용과 기대 효과가 수치화되어 ROI를 계산할 수 있는가?
   - 5점: 낙관/비관 시나리오별 ROI + 손익분기점 명시

6. **비기능 요구사항 충분성** (가중치 x1.0, 최소 ≥3)
   - 응답 시간, 가용성, 보안 기준이 수치로 정의되어 있는가?
   - 5점: 확장성(x10, x50) 대응 계획 포함

## 출력 형식

각 항목에 대해:
- **점수**: N/5
- **근거**: 점수를 준 구체적 이유 (PRD의 어떤 부분이 현실적이거나 비현실적인지)
- **EM 피드백**: (3점 미만일 때) 어떤 정보가 추가되어야 기술 의사결정이 가능한지

추가로 다음을 산출해주세요:
- **예상 총 공수 (MM/MD)**: PRD의 Functional Spec 기반으로 개략 추정
- **P0 스코프 적절성 판단**: 일정 대비 P0 범위가 현실적인지 (120% 이상이면 경고)
- **주요 기술 리스크**: 실행 중 발생할 수 있는 기술적 장애물

마지막에 **총평**과 **Pass/Fail** 판정을 내려주세요.
(통과 기준: 가중 합계 23/35 이상 + 개별 최소 점수 충족)
````
