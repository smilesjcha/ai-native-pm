# 강의 설계 방향성 — 마지막 수업, 무엇을 핵심으로 좁힐까

> Status: Active (의사결정용)

> Last Updated: 2026-06-26
> Last Author: PM 차성재 with Claude Opus 4.8

## 결론부터 (한 줄)

> **마지막 수업은 ‘많이 보여주기’가 아니라 ‘하나를 끝까지, 당신이 다시 할 수 있게’다.**
> 핵심 스파인(디자인 토큰 → 지면 전략 → 데이터 근거 → PRD → 시안 → 프로토타입 → 데모 → 정렬) **하나를 깊게** 시연하고, 나머지는 **핸드아웃·플레이북으로 가져가게** 한다. 덱 34장은 *레퍼런스*, 라이브는 *핵심만*.

---

## 1. 왜 이 고민이 필요한가 (지금의 리스크)

10주를 거의 마친 수강생에게 **새 개념을 더 얹으면 ‘많이 봤지만 못 한다’**로 끝난다. 지금 자료는 풍부하지만(덱 34장 + 플레이북 2종 + 실습 7스텝), **그대로 다 라이브로 다루면 과부하**다.

→ 전문가의 마지막 수업 = **범위를 줄이고 깊이를 올린다.** 적게 가르치고, 확실히 가져가게.

---

## 2. 세 가지 설계 원칙

1. **One spine, fully worked (하나를 끝까지)** — Shopping Mate 한 사례로 토큰부터 정렬까지 **끊김 없이** 보여준다. 여러 사례·도구를 얕게 흩지 않는다.
2. **Depth over breadth (넓이보다 깊이)** — 도구는 **Claude Code 하나**로 통일. ‘무엇을 시킬지(프롬프트·판단)’에 시간을 쓴다.
3. **Take-home over show (보여주기보다 가져가기)** — 졸업 선물 = **재현 가능한 워크플로우 + 플레이북 + 체크리스트.** "오늘 본 걸 월요일에 내 일에 한다"가 성공.

---

## 3. 핵심 vs 선택 (Core / Optional) — 라이브 큐레이션

> 라이브에서 **반드시 깊게** 다룰 것(Core)과, **언급·핸드아웃**으로 넘길 것(Optional)을 분리.

| 블록 | 라이브 비중 | 이유 |
|------|------------|------|
| **디자인 토큰 만들기** (웹 claude-design → 다운 → Claude Code) | **Core (시연)** | 모두의 출발점, ‘AI로 디자인 기반 확보’ 체감 |
| 커머스 지표 → 유저 임팩트 | Core (간결) | 분석의 언어. 표 1~2장이면 충분 |
| Agent 벤치마크 (Alexa·Clova) | **Optional (표 1장만)** | 깊게 안 가도 됨. 비교표 1장 + 핸드아웃 |
| 지면별 Agent 매트릭스 | **Core** | ‘어디에 넣을까’ 의사결정 — 실무 핵심 |
| 데이터 코호트·퍼널 | Core (시연 1회) | 근거 만드는 법. mock으로 라이브 1회 |
| 리서치 기반 메트릭 | Optional (언급) | 리서치 받으면 보강 |
| **PRD 작성 노하우** (두괄식·표·플레이북) | **Core** | 이번 강의의 심장. 집중 역할 시연 |
| 코드 기반 시안 | **Core (시연)** | 토큰 → 화면 연결 체감 |
| 프로토타입 + 데모 영상 | **Core (시연)** | ‘된다’의 증거. 라이브 하이라이트 |
| 정렬 (디자이너·개발자·리더십) | **Core (간결)** | 실서비스 적용의 마지막 관문 |
| Confluence storage format | Optional (핸드아웃) | 발행처일 때만. 플레이북으로 |
| 트랙별 응용 | Core (마무리 1장) | 내 일로 연결 |

> 라이브 스파인(Core)만: **디자인 토큰 → 지면 매트릭스 → (데이터 1회) → PRD → 시안 → 프로토타입·데모 → 정렬.** 나머지는 ‘여기 플레이북에 있으니 가져가세요’.

## 4. 시간 배분 (제안, 17:00–19:00)

| 구간 | 시간 | 내용 |
|------|------|------|
| 도입 + 오늘의 핵심·안 다루는 것 | 5분 | 기대치 정렬(과부하 방지) |
| 시연: 토큰 → PRD → 시안 → 데모 (스파인) | 25분 | One spine, 끊김 없이 |
| 실습: 각자 Core 스텝 따라 만들기 | 60분 | 디자인토큰·매트릭스·PRD·시안·데모 |
| 정렬 + 발표 + 마무리 | 20분 | 청중별 1장 + 졸업 메시지 |
| 버퍼 | 10분 | Q&A·환경 트러블 |

---

## 5. ‘안 다룬다’를 명시하라 (전문가의 신뢰)

마지막 수업에서 **무엇을 안 다루는지 먼저 말하는 것**이 전문성이다. (다 아는데 일부러 좁힌다는 신호)
- 라이브에서 생략: 벤치마크 심화·리서치 정량·Confluence 변환·다중 트랙 동시.
- 대신: "이건 플레이북/덱에 있습니다. 필요할 때 꺼내 쓰세요."

---

## 6. 적용 (이 방향으로 자료를 어떻게 쓰나)

- **덱(34장)**: 그대로 **레퍼런스/핸드아웃**. 라이브는 Core 슬라이드만 따라간다(아래 슬라이드에 Core 표식 권장).
- **실습 가이드**: 각 스텝에 **Core/Optional** 표식 (디자인 토큰 스텝 추가).
- **추가 슬라이드 2장**: ① 디자인 토큰 만들기(웹→다운→Claude Code) ② ‘오늘의 핵심 / 안 다루는 것’ 기대치 정렬.
- **더 늘리지 않는다.** 이후 요청은 ‘추가’보다 ‘교체·압축’으로.
