## P-B1. ① 디자인 토큰 확보 — DESIGN.md를 붙여 토큰 표와 CSS 변수로

**왜 먼저인가**: 토큰(색·글꼴·둥글기·간격 값의 이름표)이 있어야 시안·프로토타입·슬라이드가 같은 얼굴이 된다. 디자이너가 있는 팀은 회사 디자인 시스템의 토큰을, 없으면 공개 DESIGN.md(예: getdesign.md의 Apple 분석 `[강의 전 확인]`)를 붙인다. 이 레포는 `docs/design-system/DESIGN.md` → `tokens/tokens.css`를 이미 갖고 있으니 그 파일을 그대로 붙여도 된다.

### Lv1 무료 웹 — 붙여넣기

```text
[역할] 당신은 디자인 시스템 토큰을 정리하는 프런트엔드 디자이너입니다. 값을 새로 만들지 않고 자료에 있는 값만 옮깁니다.

[목적] 아래 DESIGN.md(디자인 분석 문서)에서 웹 시안에 필요한 최소 토큰을 뽑아, 시안 HTML의 <style> 맨 위 :root에 그대로 붙일 수 있는 CSS 변수 블록을 만듭니다.

[독자] 코드를 모르는 기획자. 값의 뜻을 한 줄씩 설명해 주세요.

[자료] --- 아래에 DESIGN.md 전문을 붙입니다. 한글 화면이므로 글꼴은 "Apple SD Gothic Neo","NanumGothic","Malgun Gothic",system-ui 순 폴백으로 지정합니다.

[형식]
1) 토큰 표 1개 — 열: 토큰 이름 | 값 | 어디에 쓰나(한 줄). 행은 색(액센트 1개·글자 2단계·배경 2개·선 1개) · 글꼴(본문·제목) · 굵기 · 둥글기(sm/md/lg/pill) · 간격(4·8·12·17·24·32) · 그림자(1개)로 20행 이내.
2) 그 표를 그대로 옮긴 CSS 코드 블록 — :root { --color-action-blue: #0066cc; ... } 형식. 주석으로 출처 줄(DESIGN.md 섹션명)을 남깁니다.
3) 표 아래 "Do / Don't" 각 3줄 — 액센트 색은 하나만, 두 번째 브랜드색 금지, 그림자는 제품 이미지에만 같은 원칙을 자료에서 찾아 옮깁니다(자료에 없으면 [확인 필요]).

[검증]
- 자료에 없는 색·수치를 추가하지 않습니다. 추가가 필요하면 값 대신 "[확인 필요]"를 씁니다.
- 액센트 색이 2개 이상 뽑혔으면 하나로 줄이고 이유를 한 줄 씁니다.
- 마지막에 "이 토큰으로 못 그리는 것 2개"를 씁니다(예: 차트 색 단계, 상태 색).
---
[여기에 DESIGN.md 전문 또는 docs/design-system/tokens/tokens.css 전문 붙이기]
```

**한 번 수정**: `토큰 이름을 우리 팀이 쓰는 이름으로 바꿔줘. 값은 그대로 두고 이름 매핑 표를 추가해줘.`

### Lv3 Claude Code 변형 (강사 시연 · 프로젝트 폴더에서)

```text
방금 받은 DESIGN.md(또는 design 폴더)를 읽고 docs/design-system 구조처럼

토큰을 한눈에 보는 style-guide.html을 만들고, 값은 DESIGN.md에 있는 것만 써. 새 값이 필요하면 [확인 필요] 주석으로 남겨.
끝나면 assets/build/shoot.js로 style-guide.html을 캡처해줘.
```

## P-B2. ② 지면별 AI 매트릭스 — 어디에 AI를 넣고 무엇으로 재나

**왜**: 시안을 그리기 전에 "어느 화면에, 어떤 AI를, 어떤 이벤트로 재는지"를 표로 고정하면 화면 수가 늘어나지 않는다. PRD §화면 섹션과 개발자의 로깅 설계가 이 표 하나에서 나온다.

```text
[역할] 당신은 핀테크 앱의 서비스 기획자입니다. 화면(지면)마다 AI가 할 일과 측정 이벤트를 짝지어 정리합니다.

[목적] 머니핏의 핵심 지면 4개(온보딩·계좌 연동 / 홈 대시보드·소비 요약 / 저축 목표 설정 2단계 / AI 코칭 카드·첫 저축 넛지)에 대해 "지면별 AI 매트릭스"를 만들어, 다음 단계(코드 시안)의 범위를 고정합니다.

[독자] 기획자·디자이너·개발자가 같은 표를 봅니다. 한 셀은 한 문장.

[자료] --- 아래 5개 핵심 입력(서비스·타겟·문제·AI 활용점·성공 기준)을 붙입니다. 퍼널 이벤트 이름은 signup → link_account → set_goal → first_saving → d30_active 다섯 개만 씁니다.

[형식] Markdown 표 1개. 행 = 지면 4개. 열 = 지면 | 사용자가 하려는 일 | AI 활용점(1~2개) | AI가 하면 안 되는 것 | 측정 이벤트(위 5개 중) | 사람이 검수하는 것 | 우선순위(1~4).
표 아래에 "이번 시안에서 뺄 것 3개"를 이유와 함께 씁니다.

[검증]
- AI 활용점에 "추천·권유"가 들어가면 "정보 제공 범위(컴플라이언스 확인 필요)"를 붙입니다.
- 측정 이벤트는 자료의 5개 이름만 씁니다. 새 이벤트가 필요하면 "[제안] 이벤트명"으로 구분합니다.
- 우선순위 1은 성공 기준의 핵심 지표(set_goal·first_saving)에 직접 닿는 지면이어야 합니다. 아니면 이유를 씁니다.
---
[여기에 lab-2 §0-1 머니핏 5개 핵심 입력 붙이기 — 내 서비스는 §0-2 빈칸 카드]
```

**한 번 수정**: `우선순위 1·2 지면만 남기고, 각 지면의 AI 문구 예시를 1개씩 "[가정]"을 붙여 써줘.`

## P-B3. ③ 코드 시안 — 단일 HTML 지면 보드 (Figma 대신)

**왜**: HTML 한 파일이면 토큰이 곧 CSS 변수여서 색·글꼴이 어긋나지 않고, 문구를 고치면 즉시 다시 캡처할 수 있으며, PRD에 PNG로 임베드하기까지 10분이 걸리지 않는다. 무료 웹에서도 미리보기(Artifact·Canvas `[강의 전 확인]`)로 바로 볼 수 있다.

### Lv1 무료 웹 — 붙여넣기 (머니핏 완성본)

```text
[역할] 당신은 디자인 토큰을 그대로 지키는 프로토타이핑 디자이너입니다. 외부 라이브러리·이미지·폰트 링크 없이 단일 HTML만 씁니다.

[목적] 머니핏의 모바일 지면 시안 보드를 HTML 파일 1개로 만듭니다. 화면 4개를 가로로 나란히 놓고, 각 화면에서 "AI 적용 지점"을 눈에 띄게 표시해 디자이너·개발자·임원이 질문 없이 범위를 이해하게 합니다.

[독자] 디자이너(착수용) · 개발자(화면 수·상태 파악) · 임원(완성도 감).

[자료] --- 아래에 ① P-B1의 :root 토큰 블록 ② P-B2의 지면별 AI 매트릭스를 붙입니다. 화면 4개: (1) 온보딩·계좌 연동 (2) 홈 대시보드·소비 요약 (3) 목표 설정 2단계(2단계 화면을 보여주되 1단계 선택 결과를 칩으로 표시) (4) AI 코칭 카드·첫 저축 넛지.

[형식]
- 단일 HTML. <style> 맨 위 :root에 토큰 변수 인라인. 글꼴은 "Apple SD Gothic Neo","NanumGothic","Malgun Gothic",system-ui 폴백.
- 어두운 보드 배경 위에 폰 프레임 4개(각 300×600px), 프레임 위에 "01 ONBOARDING" 같은 태그와 화면 이름.
- 각 화면의 AI 적용 지점은 액센트 색(#0066cc) 2px 테두리 박스 + 왼쪽 위 "AI 적용" 라벨. 박스 안은 "🤖 한 문장(사용자에게 보이는 문구)" + "무엇을 하는 AI인지 한 줄(회색 작은 글씨)".
- 각 화면 아래 캡션 3줄: 지면 — / AI 활용점 — / 측정 이벤트 — (link_account · set_goal · first_saving · d30_active 중).
- 보드 맨 위에 "교육용 가상 사례 · 머니핏(MoneyFit) by 핀트리(FinTree)" 배지, 맨 아래에 범례(파란 박스 = AI 적용 지점)와 "수치 [가정] · 인증·동의 문구는 컴플라이언스 확인 필요".
- 실제 기관·상품명 대신 "은행 A·카드사 B·은행 C". 모든 금액·비율 뒤에 [가정].

[검증]
- 액센트 색은 #0066cc 하나만 씁니다. 다른 채도 높은 색이 있으면 회색으로 바꿉니다.
- 본문 글자는 10px 이상, 캡션은 9px 이상. 프레임 밖으로 넘치는 요소가 없어야 합니다.
- 코드 맨 끝에 주석으로 "브라우저에서 열어 캡처하는 법"을 2줄로 씁니다(파일 저장 → 브라우저로 열기 → 운영체제 화면 캡처).
---
[① P-B1 토큰 블록]
[② P-B2 매트릭스]
```

**결과 확인 3개**: ① 파란 박스가 화면마다 1개 이상인가 ② 캡션의 측정 이벤트가 5개 이름 안에 있는가 ③ 실제 기관·상품명이 없는가.
**한 번 수정**: `(2)번 홈 화면의 AI 박스 문구를 "이번 달 배달비가 지난 3개월 평균보다 높아요 [가정]"처럼 사용자 말투로 바꾸고, 캡션에 '사람이 검수하는 것'을 한 줄 추가해줘.`

**Lv1에서 PNG로 만드는 법(코드 몰라도 됨)**: 미리보기 창이 열리면 그대로 운영체제 화면 캡처(macOS `Shift+Cmd+4`, Windows `Win+Shift+S`). 미리보기가 없는 도구면 코드 블록을 복사 → 메모장에 붙여 `surfaces.html`로 저장 → 더블클릭으로 브라우저에서 열기 → 캡처. 완성 예시: `workshop/builder/surfaces.html` → `assets/builder/moneyfit-surfaces.png`.

## P-B4. ④ 동작 프로토타입 — 단일 HTML 상태기계 + 자동 데모

**왜**: 시안 PNG는 "이렇게 보인다"까지고, 클릭이 되는 순간 개발자의 질문("이 버튼 누르면 어디로 가요?")이 사라진다. 상태기계(화면 상태와 전환 규칙의 목록)를 AI에게 표로 먼저 시키고, 그 표대로 HTML을 만들게 하면 화면이 늘어나지 않는다.

### Lv1 무료 웹 — 붙여넣기 (미리보기에서 클릭 체험까지)

```text
[역할] 당신은 단일 HTML 프로토타입을 만드는 프런트엔드 개발자입니다. 프레임워크·외부 스크립트 없이 HTML+CSS+JavaScript 한 파일로 만듭니다.
```

## P-B6. 정렬 — PRD에 임베드하고 청중별 한 줄을 붙인다

**왜**: 같은 에셋도 청중마다 증명하는 것이 다르다(시안 → 디자이너 착수, 프로토타입 → 개발자의 살아 있는 명세, 영상 → 임원의 확신). PRD의 화면 섹션에 넣을 때 "누가 무엇을 보면 되는지"를 한 줄씩 달아야 회의가 짧아진다.

```text
[역할] 당신은 PRD를 다듬는 시니어 기획자입니다. 이미 만들어진 시안·프로토타입·영상을 PRD에 배치하고, 청중별 읽는 법을 씁니다.

[목적] 아래 PRD 초안의 "화면·동작 방식" 섹션에 시안 보드 PNG 1장, 프로토타입 화면 PNG 2장, 데모 영상 링크 1개를 배치하고, 디자이너·개발자·임원이 각각 무엇을 확인하면 되는지 한 줄씩 붙입니다.

[독자] 디자이너·개발자·임원이 같은 PRD를 읽습니다.

[자료] --- 아래에 ① PRD 초안(§화면 섹션 포함) ② 에셋 목록(파일명·캡션)을 붙입니다.

[형식]
- §화면 섹션을 다음 구조로 재작성: (a) 지면 시안 보드 이미지 + 캡션(AI 적용 지점 4곳) (b) 핵심 화면 2장(목표 설정 2단계 · 코칭 카드) + 각 화면의 측정 이벤트 (c) 데모 영상 링크 + "27초 · 연동→첫 저축" 한 줄.
- 그 아래 표 1개 "누가 무엇을 확인하나": 행 = 디자이너 / 개발자·EM / 임원, 열 = 보는 에셋 | 확인할 것 1줄 | 결정해 줄 것 1줄.
- 이미지 참조는 상대경로 Markdown(![캡션](assets/builder/파일명.png))으로 씁니다.

[검증]
- 에셋에 없는 화면을 언급하지 않습니다. 시안과 PRD 본문의 화면 수가 다르면 그 차이를 "[확인 필요]"로 표시합니다.
- 시안의 모든 수치가 [가정]임을 §화면 섹션 첫 줄에 명시합니다.
- 마지막 문장은 요청으로 끝냅니다(예: "디자이너는 시안 착수 여부, 개발은 이벤트 파라미터 확정, 임원은 범위 승인을 9/26까지 결정해 주십시오 [가정]").
---
[① PRD 초안]
[② 에셋 목록 — README.md §2 표를 그대로 붙이기]
```
