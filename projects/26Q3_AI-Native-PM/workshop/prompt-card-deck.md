> **교육용 가상 데이터** — 이 덱의 모든 사례·회사·서비스·수치·조항 번호는 교육용으로 만든 가상 자료입니다. "머니핏(MoneyFit)"과 "핀트리(FinTree)"는 실제 기업·상품이 아닙니다. 수치는 `[가정]`, 확인 전 정보는 `[확인 필요]`입니다. 이 덱은 법률 자문이 아니며, 규제 관련 결과는 컴플라이언스 확인이 필요합니다.

> 이 덱은 `lab-1-prompt-design.md`·`lab-2-prd-draft.md`·`lab-3-automation-workflow.md`의 코드 블록을 **한 글자도 바꾸지 않고** 실행 순서대로 모은 것입니다. 카드마다 원본 위치를 적었습니다. 카드 설명이 lab 파일과 다르게 읽히면 **lab 파일이 원본**입니다. 금융 도메인 템플릿 7종(《 》치환형)은 별도 파일 `prompt-templates-fintech.md`에 있습니다.

## 사용법 (30초)

1. 카드의 코드 블록(회색 상자) **전체**를 복사해 붙입니다. 일부만 복사하면 검증 조건이 빠집니다. 프롬프트 가운데를 편집하지 않습니다.
2. 카드의 **대화창** 표시를 따릅니다. 검수(P03)·리뷰(P08)는 **반드시 새 대화**에서 — 초안을 만든 대화에서 "맞지?"라고 물으면 동조합니다.
3. 코드 블록 끝에 `---` 와 `▼ … 붙여넣기 ▼` 가 있는 카드(P07·P08·P09)는 **프롬프트 붙이기 → 맨 아래로 이동 → `---` 다음에 내 자료 붙이기 → 전송** 3동작입니다. `[여기에 … 붙여넣기]` 자리가 있는 카드(P12·P15)는 그 자리에 자료를 넣습니다.
4. `《 》`·`[서비스 1]` 같은 자리만 내 값으로 바꿉니다. `[역할]`~`[검증]` 라벨과 `[가정]`·`[확인 필요]` 태그는 그대로 둡니다. Session 3 카드(P10~P15)는 라벨을 `역할:`처럼 콜론으로 쓰지만, 오전 카드의 `[역할]`~`[검증]`과 같은 **요청 6요소(역할·목적·독자·자료·형식·검증)** 입니다 — 순서와 뜻은 동일합니다.
5. **결과가 강사·옆사람과 달라도 정상**입니다. 카드의 **결과 체크 3개**만 확인하고, 실패한 항목에 **재요청 문장 1개**를 같은 대화에 붙입니다. 프롬프트를 처음부터 다시 쓰지 않습니다.
6. 붙이기 전 **입력 전 30초 체크**(부록 B: 사람·회사·고객·권한). 실제 고객·거래·내부 데이터·실명·연락처는 오늘 어디에도 넣지 않습니다.

### 프롬프트 전문

```text
[역할] 당신은 마이데이터 기반 핀테크 서비스를 기획하는 시니어 서비스 기획자입니다.
[목적] 아래 5개 핵심 입력을 바탕으로, 팀 내부 검토용 서비스 기획 초안을 만듭니다. 초안의 목적은 "이 방향으로 PRD를 본격 작성할지"를 프로덕트 리드가 결정하는 것입니다.
[독자] 독자는 프로덕트 리드와 컴플라이언스 담당자입니다. 두 사람 모두 5분 안에 읽고 결정해야 합니다.
[자료] 아래 자료만 근거로 사용하세요. (교육용 가상 사례)
- 서비스명: 머니핏(MoneyFit) — 가상 회사 핀트리(FinTree)
- 타겟 유저: 25~35세 직장인. 급여는 있으나 계좌·카드가 분산되어 소비 파악이 어렵다 [가정]
- 핵심 문제: "내 돈이 어디로 가는지 모른다". 저축 목표를 세워도 3개월 내 이탈률 70% [가정]
- AI 활용점: 거래 내역 자동 분류·요약, 소비 패턴 인사이트, 개인화 코칭 문구, 목표 달성 시뮬레이션
- 성공 기준 후보: 첫 저축 목표 설정율, 자동 저축 실행율, 30일 리텐션 — Baseline·Target 미정 [가정]
- 알려진 규제 키워드: 본인신용정보관리업(마이데이터) 허가·전송요구권, 신용정보법, 개인정보보호법(가명처리), 금융소비자보호법·자본시장법(AI 코칭 문구가 투자 권유·투자자문에 해당하는지 여부 — 컴플라이언스 확인 필요), 전자금융거래법
[형식] 한국어 Markdown. 순서: ① 결론부터(3문장: 무엇을·왜·성공 기준) ② 문제와 타겟 ③ 솔루션 개요와 AI 활용점 ④ 성공 지표 표(열: 지표 | Baseline | Target | 측정 이벤트) ⑤ 규제·리스크 체크 표(열: 항목 | 우리 서비스와의 관련성 | 컴플라이언스에 물어볼 질문) ⑥ 확인 필요 목록 ⑦ 다음 액션. A4 1~2페이지.
[검증] 자료에 없는 숫자나 사실은 만들지 말고 [확인 필요]로 표시하세요. 추정은 [가정]으로 표시하세요. 시장 규모·경쟁사 기능·법령 조항은 자료에 없으면 본문에 쓰지 말고 확인 필요 목록으로 옮기세요. 규제 관련 문장은 단정하지 말고 "컴플라이언스 확인 필요"를 붙이세요. 마지막 문장은 프로덕트 리드에게 요청할 결정을 한 문장으로 쓰세요.
```

### 결과 체크 3개 (lab-1 §1.4 Step 2)

- [ ] **목차**: 내가 `[형식]`에 쓴 순서대로 나왔나 (예시 완성본이면 ①~⑦)
- [ ] **표기**: `[확인 필요]`·`[가정]`이 보이나 — **0개면 좋은 결과가 아니라, 자료에 없는 것을 전부 채웠다는 신호**
- [ ] **마지막 문장**: 독자에게 요청하는 문장으로 끝났나

### 재요청 문장 (Step 3 · 부록 A 10선 중 **1개만** · 처음이면 1번 또는 5번)

```text
1. 자료에 없는 숫자·사실은 모두 [확인 필요]로 바꾸고, 어느 자료 항목이 근거인지 각 문장 뒤에 괄호로 표시해 주세요.
```

```text
5. 이 초안에서 근거가 가장 약한 3곳을 골라, 왜 약한지와 누구에게 무엇을 확인해야 하는지를 표(열: 문장 | 왜 약한가 | 확인 질문 | 확인 대상)로 써 주세요.
```

> 결과에서 무엇이 바뀌었는지 1줄로 메모한다(예: "[확인 필요]가 0개 → 4개로 늘고 시장 규모 문장이 사라짐"). 생성을 기다리는 동안 P02의 `[자료]` 칸만 내 업무의 치환된 값으로 메모한다 — 오후 v2의 씨앗.

### 프롬프트 전문

```text

- 지표: 목표 설정율(연동 대비) 72.5% → 80% [가정] / 첫 저축율(목표 대비) 71.0% → 78% [가정] / 30일 활성 30.0% → 35% [가정]. 측정: set_goal·first_saving·d30_active 이벤트

독자: 10분 안에 v1.1 착수 여부를 결정하는 임원. 배경 설명보다 결론·지표·요청을 먼저 봅니다.
자료: 아래 기획서(교육용 가상 사례)와, 있다면 퍼널 분석 결과. 이 안에 없는 정보는 쓰지 않습니다.
---
[여기에 PRD 또는 2-Pager 붙여넣기]
---
형식: 10장 고정, 순서는 다음과 같습니다.
1 표지 / 2 결론(한 문장) + 요청 / 3 배경(왜 지금) / 4 문제(숫자 1개) / 5 해결(무엇을 만드는가) / 6 동작 방식 또는 화면 예시 / 7 지표(Baseline → Target → 측정 방법) / 8 리스크·규제 체크 / 9 일정·리소스 / 10 요청(결정 사항 1~2개)
각 장을 표 1행으로 씁니다. 열: # | 제목(결론 문장, 2줄 이내, "배경"·"현황" 같은 명사 제목 금지) | 요점 3개(각 1줄) | 시각 요소 제안(표·차트·화면·다이어그램 중 1개, 무엇을 보여줄지) | 발표자 노트(30초 분량, 말로 할 문장)
검증: 표를 다 쓴 뒤 제목만 위에서 아래로 읽어 논리가 이어지는지 스스로 점검하고 "제목만 읽은 요약" 3문장을 덧붙이세요. 자료에 없는 숫자나 사실은 만들지 말고 [확인 필요]로 표시하고, 목표 수치는 [가정] 표기를 유지하세요. 규제 관련 문장은 단정하지 말고 "컴플라이언스 확인 필요"를 붙이세요. 2장과 10장의 요청이 같은 내용인지 확인하세요.
```

# 부록 A. 재요청 문장 10선 (모든 카드 공통 · Step 3에서 1개만)

> 출처: `lab-1-prompt-design.md` §1.5 — 재요청 10선의 **단일 원본**(`prompts-txt/lab-1-rerequest-10.txt`와 동일). `prompt-templates-fintech.md` §8은 이 원본을 참조하고 번호 요약만 싣습니다("왜 외우나"는 §8 인용). 그대로 인용.

```text
1. 자료에 없는 숫자·사실은 모두 [확인 필요]로 바꾸고, 어느 자료 항목이 근거인지 각 문장 뒤에 괄호로 표시해 주세요.
2. 결론을 맨 위 3문장으로 올리고, 나머지는 그 결론의 근거 순서로 재배열해 주세요.
3. 본문과 표가 같은 말을 하면 표만 남기고, 본문은 해석 한 줄로 줄여 주세요.
4. 분량을 절반으로 줄이되 숫자·[확인 필요] 표기·마지막 요청 문장은 그대로 유지해 주세요.
5. 이 초안에서 근거가 가장 약한 3곳을 골라, 왜 약한지와 누구에게 무엇을 확인해야 하는지를 표(열: 문장 | 왜 약한가 | 확인 질문 | 확인 대상)로 써 주세요.
6. 독자를 《컴플라이언스 담당자》로 바꿔, 같은 자료로 그 독자가 결정해야 할 것 중심으로 다시 써 주세요. 자료에 없는 숫자·조항은 만들지 말고 [확인 필요]로 표시하고, 규제 문장은 단정하지 마세요.
7. 규제·법령 관련 문장은 모두 단정을 없애고 "컴플라이언스 확인 필요"를 붙인 뒤, 컴플라이언스에 물어볼 질문 목록으로 따로 모아 주세요.
8. 표의 마지막 열에 "우리에게 시사점 / 다음 액션"을 추가하고, 빈 셀은 —로 표시해 주세요.
9. 지표마다 Baseline · Target · 측정 이벤트 3개가 있는지 점검하고, 없는 것은 [가정] 또는 [확인 필요]로 채워 주세요.
10. 이 결과를 내가 검수할 때 확인해야 할 질문 5개를 만들어 주세요. 자료에 없는 숫자나 사실은 만들지 마세요.
```

왜 외우나: 첫 답이 나빠도 당황하지 않고, 프롬프트 전체를 다시 쓰는 낭비를 막는다. 1·5·7·10은 금융 문서에서 특히 자주 쓴다.

# 부록 B. 입력 전 30초 체크리스트 (사람·회사·고객·권한) + 치환 예시

> 출처: `prompt-templates-fintech.md` §9. 그대로 인용.

붙여넣기 전, 4가지만 확인한다.

- [ ] **사람** — 실명·연락처·식별 가능한 개인정보가 있는가? → 역할명·"담당자A"로 치환 또는 삭제
- [ ] **회사** — 미공개 실적·전략·계약·인사 정보가 있는가? → 가상 값(X억·N건)으로 치환
- [ ] **고객** — 고객을 특정할 수 있는 정보(계좌·카드·거래 내역·상담 기록)가 있는가? → "고객A"·집계값으로 치환, 가명처리 여부는 회사 기준 확인 `[확인 필요]`
- [ ] **권한** — 이 자료를 외부 서비스에 올릴 권한이 나에게 있는가? 회사가 승인한 환경(2층)인가? → 모르면 올리지 않는다

### 치환 예시 (금융 기획 업무)

| 원본 예시 — 전부 가상(넣지 않는 것) | 치환(넣는 것) | 구조가 유지되는가 |
|------------------|-------------|----------------|
| 홍○○ 고객(계좌 XXX-***-****), 8월 카드 결제 47건 [가정] | 고객A, 8월 카드 결제 N건 [가정] | 유지 — 분류·요약 품질에 영향 없음 |
| 8월 마이데이터 연동 계좌 12만 4천 건, 전환율 38.2% [가정] | 8월 연동 계좌 N건, 전환율 X% [가정] (또는 임의 값 100건·40%) | 유지 — 해석 프롬프트는 비율 구조만 필요 |
| ○○은행 제휴 조건: 자동 저축 계좌 우대금리 연 0.3%p [가정] | 제휴사B, 우대 조건 Y [확인 필요] | 유지 — 조건 자체는 약관 대조(템플릿 b)에서 원문으로 |
| 내부 리스크 등급 3등급 고객 세그먼트 [가정] | 세그먼트 C(내부 기준) | 유지 — 등급 정의는 넣지 않음 |
| 2026 하반기 미공개 사업 계획: (가상 예시) | (미공개 전략 — 치환 불가 시 입력하지 않음) | — 입력 금지 |
| 김○○ 대리, 연락처 0XX-****-**** | 담당자A(운영) | 유지 |
| 킥오프 회의 참석자 실명 5인 | 역할A(PM)·역할B(개발 리드)·역할C(컴플라이언스)·역할D(디자인)·역할E(데이터) | 유지 — 회의록(d)은 역할만 필요 |

> 위 표의 원본 열은 형태를 보여주기 위한 **가상 예시**이며 실제 고객·거래·전략 정보가 아니다. 구조만 유지되면 AI의 도움 품질은 거의 떨어지지 않는다. **"치환 후 입력 → 결과에 실제 값 복원"** 이 안전한 기본 습관이다. 회사가 승인한 환경(2층)에서 내부 데이터를 다룰 때도 회사 내부 가이드가 정한 범위가 우선이며, 법적 판단은 컴플라이언스 확인이 필요하다.
