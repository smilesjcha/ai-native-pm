## 가상 사례 배경 (한 줄)

머니핏은 마이데이터 기반 2030 직장인 자산관리 코칭 서비스(가상)입니다. 사용자는 **가입(signup) → 계좌·카드 연동(link_account) → 저축 목표 설정(set_goal) → 첫 저축 실행(first_saving) → 가입 30일 후에도 활성(d30_active)** 순서로 나아가며, 이 다섯 단계를 퍼널로 봅니다. 데이터 추출 기준일은 2026-10-05 `[가정]`이므로 8월 말 가입자도 30일이 지난 상태입니다.

## 데이터 딕셔너리

### `moneyfit-events.csv`

| 컬럼 | 타입 | 값·범위 | 설명 |
|------|------|--------|------|
| `user_id` | 문자열 | `U0001`–`U0500` | 가상 사용자 식별자(500명). 개인정보 아님 |
| `signup_date` | 날짜(YYYY-MM-DD) | 2026-06-01 ~ 2026-08-31 | 가입일. 같은 사용자의 모든 행에 동일하게 반복 |
| `age_band` | 범주 | `25-29` / `30-34` / `35-39` | 연령대 구간(개별 나이 없음) |
| `channel` | 범주 | `app_store` / `play_store` / `referral` / `ad` | 유입 채널: 앱스토어 / 플레이스토어 / 지인 추천 / 광고 |
| `event` | 범주 | `signup` → `link_account` → `set_goal` → `first_saving` → `d30_active` | 퍼널 단계. 한 사용자는 도달한 단계까지만 행이 있음 |
| `event_date` | 날짜(YYYY-MM-DD) | 2026-06-01 ~ 2026-10-04 | 해당 단계가 발생한 날. `d30_active`는 가입 후 30–34일 사이 |

- 한 사용자 = 도달한 단계 수만큼의 행(1–5행). 퍼널 전환율은 **단계별 고유 `user_id` 수**로 계산합니다.
- 설계 잔존율(전체 기준) 100 → 78 → 55 → 38 → 27% 근처가 되도록 생성했고, 채널·연령대별로 전환이 다르게 설계했습니다(아래 정답표).

### `moneyfit-transactions.csv`

| 컬럼 | 타입 | 값·범위 | 설명 |
|------|------|--------|------|
| `txn_id` | 문자열 | `T00001`–`T00602` | 가상 거래 식별자 |
| `user_id` | 문자열 | `U0001`–`U0500` 중 계좌를 연동한 사용자 | 이벤트 파일과 조인 가능 |
| `txn_date` | 날짜 | 2026-08-01 ~ 2026-08-31 | 거래일(8월 한 달) |
| `category` | 범주 | 식비 / 교통 / 구독 / 쇼핑 / 저축 / 공과금 / 여가 | 소비 카테고리(저축은 저축 계좌 입금) |
| `amount` | 정수(원) | -89,000 ~ 1,850,000 | 거래 금액. 음수 1건은 환불로 보이는 의도적 이상치 |

## 정답표 — 강사·조교용 (수강생 결과 대조)

아래 값은 `generate-sample-data.py`(seed 20260919)로 생성한 파일을 그대로 집계한 값입니다. AI 도구가 낸 숫자를 이 표와 대조하세요. **결과가 다르면 이상치 처리 방식이 다른 것**이 대부분입니다(아래 "의도적 이상치" 참조).

### 전체 퍼널 (원본 그대로 · 고유 사용자 수 기준)

| 단계 | 사용자 수 | 전체 대비 | 직전 단계 대비 |
|------|--------:|--------:|-----------:|
| signup | 500 | 100.0% | — |
| link_account | 387 | 77.4% | 77.4% |
| set_goal | 279 | 55.8% | 72.1% |
| first_saving | 198 | 39.6% | 71.0% |
| d30_active | 150 | 30.0% | 75.8% |

- 이상치(중복 2행·가입일 이전 이벤트 3행)를 제거하면 `link_account`가 **385명(77.0%)** 으로 바뀌고 나머지는 같습니다. 이 2명 차이가 "이상치를 먼저 보는 이유"의 시연 소재입니다. **3행을 뺐는데 왜 2명만 줄어드나**: `U0042`는 가입일 이전 `link_account` 행 외에 정상 `link_account` 행(2026-07-29)이 하나 더 있어 사용자 수에서 빠지지 않고, `U0187`·`U0333` 2명만 빠집니다(고유 사용자 수 기준 계산의 예시).
- "가장 큰 이탈 구간"은 정의에 따라 답이 다릅니다. **이탈 인원**으로 보면 signup→link_account가 가장 크다(원본 113명 = 500−387 / 이상치 제거 후 115명 = 500−385 — 강사 시연 S3-06과 아래 채널별·연령대별 표는 이상치 제거 후 115명 기준). **직전 단계 대비 전환율**로 보면 set_goal→first_saving(71.0%)이 가장 낮습니다(두 기준 모두 동일). 실습에서는 이 차이를 수강생이 스스로 발견하는 것이 목표입니다.

## 의도적 이상치 (교육용, 정답 공개)

AI가 "이상치·데이터 품질 이슈를 찾아 표로 정리"할 때 **아래 6건을 찾는지** 확인합니다. 찾지 못하면 "가입일보다 앞선 이벤트가 있는지, 완전히 같은 행이 있는지, 선행 단계 없이 후행 단계만 있는 사용자가 있는지 확인해줘"로 한 번 더 요청합니다.

| # | 파일 | 유형 | 건수 | 위치 | 재현한 실무 상황 | 권장 처리 |
|---|------|------|----:|------|----------------|----------|
| 1 | events | 이벤트 날짜가 가입일보다 앞선 행 | 3 | `U0042`, `U0187`, `U0333`의 `link_account` | 단말 시계 오류·타임존 처리 오류 | 원인 확인 전까지 제외하고 `[확인 필요]` 표기. 비고: `U0042`는 정상 `link_account` 행이 별도로 있어 이 3행을 빼도 연동 사용자 수는 2명만 감소(`U0187`·`U0333`) → 387 → 385 |
| 2 | events | 완전 중복 행 | 2 | `U0105`, `U0260`의 `signup` | 이벤트 중복 적재 | 제거(고유 사용자 수 기준 계산이면 영향 없음) |
| 3 | events | 선행 단계 없이 후행 단계만 존재 | 1 | `U0077`(`link_account` 없이 `set_goal`) | 로그 누락 또는 수동 설정 경로 | 제외하지 말고 "연동 로그 누락 가능성" `[확인 필요]` |
| 4 | transactions | 고액 거래 | 1 | `T00601` 쇼핑 1,850,000원 | 정상 대형 구매 vs 오류 — 데이터만으로 판단 불가 | 평균 대신 중앙값 병기, 제외 여부는 `[확인 필요]` |
| 5 | transactions | 음수 금액 | 1 | `T00602` 쇼핑 -89,000원 | 환불·취소 부호 규칙 | 부호 규칙 확인 전 합계에서 분리 |

## 재생성 방법

```bash
cd projects/26Q3_AI-Native-PM/workshop/sample-data
python3 generate-sample-data.py
```

- Python 3.8 이상, 추가 패키지 없음(`csv`, `random`, `datetime`만 사용).
- `random.seed(20260919)`가 고정되어 있어 같은 파일이 재생성됩니다. 행 수·분포를 바꾸려면 스크립트 상단의 `N_USERS`, `N_TXN`, `BASE_STEP_CONV`, `CHANNEL_MULT`, `AGE_MULT`를 수정합니다.
- 스크립트는 콘솔에 퍼널·채널·연령대·카테고리 요약을 출력하므로, 값을 바꿨다면 이 README의 정답표도 함께 갱신합니다.
- `moneyfit-kickoff-meeting-notes.md`와 이 README는 수작업 문서이며 스크립트가 덮어쓰지 않습니다.

## 사용 규칙 (수강생 안내문과 동일)

1. 이 데이터는 외부 AI 서비스(ChatGPT·Claude·Gemini 등)에 올려도 되는 **교육용 가상 데이터**입니다.
2. 같은 형식이라도 **실제 회사 데이터는 회사가 승인한 환경에서만** 다룹니다. 개인정보 컬럼 제거·가명처리 여부는 컴플라이언스 확인 필요.
3. AI가 낸 숫자는 이 README의 정답표 또는 스프레드시트 재계산으로 **한 번은 직접 확인**합니다.
