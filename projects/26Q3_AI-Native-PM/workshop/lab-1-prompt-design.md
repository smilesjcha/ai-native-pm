### 0.2 계정 로그인 (체크 4개)

- [ ] 내 환경: □ 개인 계정 □ 회사 승인 계정 □ 둘 다 — 오늘 실습은 **개인 계정(1층)** 기준, 가상 데이터만 사용
- [ ] 오늘 실습 도구 1개: □ ChatGPT □ Claude □ Gemini — **무료 웹 계정**으로 충분. 설치·결제·연동 없음
- [ ] 로그인 완료 — 새 대화를 열 수 있는 상태
- [ ] 한도 도달 시 두 번째 도구: □ ChatGPT □ Claude □ Gemini — 무료 플랜은 사용량 한도가 있음 `[강의 전 확인]`. 한도에 닿으면 같은 프롬프트를 두 번째 도구에 붙여넣기

로그인은 **오프닝(09:30대) 안전 규칙 장표에서 30초간 현장 확인**합니다 — 그 자리에서 안 되면 바로 페어를 지정하니 손을 들어 주세요. 개인 휴대폰 웹 접속 또는 옆 사람과 페어로 진행합니다. 프롬프트 카드는 노트에 손으로 써도 학습 목표(요청 6요소 구조)는 달성됩니다. 가능하면 강의 시작 전(09:20까지) 로그인을 마쳐 두세요.

### 0.3 안전 규칙 3줄 (금융권 필수)

1. **실데이터 금지** — 실제 고객·거래·내부 문서·실명·연락처는 오늘 어디에도 넣지 않는다.
2. **치환** — 구조만 남기고 가상 값으로 바꾼다(고객A · N건 · X억 · 제휴사B). 치환 후 입력 → 결과에 실제 값 복원.
3. **검증** — AI 결과는 초안이다. 숫자·규제 조항·상품 조건·경쟁사 기능은 원문과 대조한다.

**입력 전 30초 체크리스트** — 붙여넣기 전에 4가지만: □ 사람(실명·연락처?) □ 회사(미공개 실적·전략·계약?) □ 고객(특정 가능한 정보?) □ 권한(이 자료를 외부 서비스에 올릴 권한이 나에게 있나? 모르면 올리지 않기)

### 0.4 오늘 실습의 공통 규칙

- 모든 실습은 **입력 → 결과 확인 → 한 번 수정** 3단계로 고정합니다.
- **결과가 강사·옆사람과 달라도 정상입니다.** 우리는 세 가지만 함께 확인합니다: 목차(요청한 순서) · `[확인 필요]`·`[가정]` 표기 · 마지막 요청 문장 — 표가 있으면 열 이름까지.
- 프롬프트는 코드 블록 **전체**를 복사해 새 대화에 그대로 붙여넣습니다. 일부만 복사하면 검증 조건이 빠집니다.

## 1. 실습 ① — 내 업무 프롬프트 템플릿 카드 (15분)

| 항목 | 내용 |
|------|------|
| 목표 | **요청 6요소(역할·목적·독자·자료·형식·검증)** 카드를 실행하고, 재요청 한 문장으로 고쳐 다시 받아 본다. 오늘의 학습 목표는 '고쳐 다시 받는 경험'이며, 내 업무 카드 6칸 완성은 캐치업·오후로 이월해도 된다 |
| 시간 | 15분(강사 안내 1.5 포함) = Step 1 입력 3분 · Step 2 결과 확인 4분 · Step 3 한 번 수정 5분 · 저장 메모 1.5분 |
| 기본 경로(권장) | §1.3 머니핏 완성본을 **그대로 실행** → 생성 대기 중 §1.2 빈 카드의 `[자료]` 칸만 내 업무로 메모 → 재요청 1개. 내 업무 카드 6칸 전체 작성은 11:10–11:30 캐치업에서. `[자료]` 메모는 오후 기획서 실습(13:25) Step 1의 5개 핵심 입력 카드(lab-2 §0-2)로 옮겨 씁니다(= 카드 v2) |
| 선택 경로 | 내 업무 6요소를 3분 안에 쓸 수 있는 분만 §1.2 카드로 시작. 단, Step 3(재요청)에 도달하는 것이 우선 |
| 산출물 | **템플릿 카드 v1**(실행한 카드 + 내 업무 `[자료]` 메모, 파일 또는 노트) + 실행 결과 + 재요청 후 "무엇이 바뀌었나" 1줄 메모 |
| 준비물 | 로그인된 무료 계정 1개 · 이 문서 §1.2 카드 · §1.3 예시 완성본 · §1.5 재요청 문장 10선 |

### 1.1 요청 6요소 한눈에

| 요소 | 이 칸이 답하는 질문 | 빠지면 생기는 일 |
|------|-------------------|----------------|
| 역할 | AI가 어떤 사람의 관점·어휘로 답해야 하나 | 일반 블로그 톤 |
| 목적 | 이 산출물로 **누가 무엇을 결정**하나 | 결론 없는 설명문 |
| 독자 | 누가 읽고, 시간·전문성·질문은 무엇인가 | 임원에게 10페이지 |
| 자료 | 근거로 쓸 사실·가정·확인 필요 — **이것만** 쓰라고 제한 | 시장 규모·규제 조항·경쟁사 기능을 추측으로 채움 |
| 형식 | 순서·분량·표 열 이름·언어·금지 사항 | 결과마다 구조가 달라 비교 불가 |
| 검증 | "자료에 없는 숫자나 사실은 만들지 말고 [확인 필요]로 표시" · 추정은 [가정] · 규제는 "컴플라이언스 확인 필요" · 마지막 문장은 요청 | 그럴듯한 숫자·조항이 초안에 박혀 문서 전체를 못 쓰게 됨 |

### 1.2 템플릿 카드 (빈칸) — 《 》만 내 업무로 바꿔 채우세요

> **표기 규칙 한 줄**: `《 》` 안만 내 내용으로 바꿉니다. `[역할]`~`[검증]` 여섯 라벨과 `[가정]`·`[확인 필요]` 태그는 **그대로 둡니다**(라벨은 AI가 구조를 읽는 기준이고, 태그는 결과에 그대로 나와야 하는 표기입니다).

```text
[역할] 당신은 《업종·조직 맥락》에서 일하는 《역할, 예: 마이데이터 서비스 기획자 / 주간 지표 리뷰 담당자》입니다.
[목적] 이 요청의 목적은 《누가》가 《무엇을 결정·실행》할 수 있도록 《산출물 종류》를 만드는 것입니다.
[독자] 독자는 《누구, 역할로》이며, 《읽는 시간·상황, 예: 회의 전 5분》에 읽고 《무엇을 결정》합니다.
[자료] 아래 자료만 근거로 사용하세요. (실데이터 금지 — 구조만 남기고 치환한 값)
- 확인된 사실: 《사실 1》, 《사실 2》
- 가정: 《가정 1》 [가정]
- 확인 필요(아직 모르는 것): 《항목 1》, 《항목 2》
[형식] 한국어. 순서: 《① … ② … ③ …》. 분량: 《예: A4 1페이지 / 600자 이내》. 표가 필요하면 열 이름은 정확히 《열A | 열B | 열C》.
[검증] 자료에 없는 숫자나 사실은 만들지 말고 [확인 필요]로 표시하세요. 추정은 [가정]으로 표시하세요. 규제·법령 관련 문장은 단정하지 말고 "컴플라이언스 확인 필요"를 붙이세요. 마지막 문장은 《독자》에게 요청할 《결정·행동》을 한 문장으로 쓰세요.
```

카드를 채울 때 3가지: ① `[검증]` 문단과 여섯 라벨·`[가정]`·`[확인 필요]` 태그는 지우지 않습니다(《 》만 바꿉니다) ② `[자료]`가 비어 있으면 "확인된 사실: 없음(초안 단계)"이라고 써서라도 칸을 채웁니다 ③ 회사 원문을 붙이지 말고 §0.3 치환 규칙대로 바꿉니다.

### 1.3 예시 완성본 1개 — 머니핏 서비스 기획 초안 요청 (기본 경로: 이걸 그대로 실행)

PRD(Product Requirements Document, 제품 요구사항 정의서)를 본격 작성하기 전 단계의 초안 요청입니다. 《 》 변수가 없는 완성본이므로 그대로 복사해 실행합니다.

```text
[역할] 당신은 마이데이터 기반 핀테크 서비스를 기획하는 시니어 서비스 기획자입니다.
[목적] 아래 5개 핵심 입력을 바탕으로, 팀 내부 검토용 서비스 기획 초안을 만듭니다. 초안의 목적은 "이 방향으로 PRD를 본격 작성할지"를 프로덕트 리드가 결정하는 것입니다.
[독자] 독자는 프로덕트 리드와 컴플라이언스 담당자입니다. 두 사람 모두 5분 안에 읽고 결정해야 합니다.
[자료] 아래 자료만 근거로 사용하세요. (교육용 가상 사례)
- 서비스명: 머니핏(MoneyFit) — 가상 회사 핀트리(FinTree)
- 타겟 유저: 25~35세 직장인. 급여는 있으나 계좌·카드가 분산되어 소비 파악이 어렵다 [가정]
- 핵심 문제: "내 돈이 어디로 가는지 모른다". 저축 목표를 세워도 3개월 내 이탈률 70% [가정]
- AI 활용점: 거래 내역 자동 분류·요약, 소비 패턴 인사이트, 개인화 코칭 문구, 목표 달성 시뮬레이션
- 성공 기준 후보: 첫 저축 목표 설정율, 자동 저축 실행율, 30일 리텐션 — Baseline·Target 미정 [가정]
- 알려진 규제 키워드: 본인신용정보관리업(마이데이터) 허가·전송요구권, 신용정보법, 개인정보보호법(가명처리), 금융소비자보호법·자본시장법(AI 코칭 문구가 투자 권유·투자자문에 해당하는지 여부 — 컴플라이언스 확인 필요), 전자금융거래법
[형식] 한국어 Markdown. 순서: ① 결론부터(3문장: 무엇을·왜·성공 기준) ② 문제와 타겟 ③ 솔루션 개요와 AI 활용점 ④ 성공 지표 표(열: 지표 | Baseline | Target | 측정 이벤트) ⑤ 규제·리스크 체크 표(열: 항목 | 우리 서비스와의 관련성 | 컴플라이언스에 물어볼 질문) ⑥ 확인 필요 목록 ⑦ 다음 액션. A4 1~2페이지.
[검증] 자료에 없는 숫자나 사실은 만들지 말고 [확인 필요]로 표시하세요. 추정은 [가정]으로 표시하세요. 시장 규모·경쟁사 기능·법령 조항은 자료에 없으면 본문에 쓰지 말고 확인 필요 목록으로 옮기세요. 규제 관련 문장은 단정하지 말고 "컴플라이언스 확인 필요"를 붙이세요. 마지막 문장은 프로덕트 리드에게 요청할 결정을 한 문장으로 쓰세요.
```

### 1.4 진행 3단계

**Step 1 · 입력 (3분)**
1. 도구에서 **새 대화**를 열고 §1.3 예시 완성본 코드 블록 전체를 붙여넣어 실행한다(기본 경로). 선택 경로면 §1.2 카드의 《 》를 내 업무로 채운 뒤 §0.3 입력 전 30초 체크리스트(사람·회사·고객·권한)를 통과했는지 보고 붙여넣는다.
2. 생성을 기다리는 동안(1~2분) §1.2 빈 카드를 메모장에 복사해 두고, `[자료]` 칸만 내 업무의 치환된 값으로 메모한다 — 이것이 오후 v2의 씨앗이다.

**Step 2 · 결과 확인 (4분)** — 체크 3개만
- [ ] **목차**: 내가 `[형식]`에 쓴 순서대로 나왔나 (예시 완성본이면 ①~⑦)
- [ ] **표기**: `[확인 필요]`·`[가정]`이 보이나 — **0개면 좋은 결과가 아니라, 자료에 없는 것을 전부 채웠다는 신호**
- [ ] **마지막 문장**: 독자에게 요청하는 문장으로 끝났나

**Step 3 · 한 번 수정 (5분)**
1. §1.5 재요청 문장 10선 중 **1개만** 골라 같은 대화에 붙여넣는다. 처음이면 1번 또는 5번 추천(1번: [확인 필요] 표기가 늘어 변화가 바로 눈에 보임 / 5번: 오전 마지막 검수 실습과 이어지는 검수 습관).
2. 결과에서 무엇이 바뀌었는지 1줄로 메모한다(예: "[확인 필요]가 0개 → 4개로 늘고 시장 규모 문장이 사라짐").
3. (저장 1.5분) 실행한 카드 + 내 업무 `[자료]` 메모 상단에 `v1 · 2026-09-19 · 도구명`을 적어 저장한다(§3 저장 안내).

### 1.5 재요청 문장 10선 — Step 3에서 1개만 고른다

```text
1. 자료에 없는 숫자·사실은 모두 [확인 필요]로 바꾸고, 어느 자료 항목이 근거인지 각 문장 뒤에 괄호로 표시해 주세요.
2. 결론을 맨 위 3문장으로 올리고, 나머지는 그 결론의 근거 순서로 재배열해 주세요.
3. 본문과 표가 같은 말을 하면 표만 남기고, 본문은 해석 한 줄로 줄여 주세요.
4. 분량을 절반으로 줄이되 숫자·[확인 필요] 표기·마지막 요청 문장은 그대로 유지해 주세요.
5. 이 초안에서 근거가 가장 약한 3곳을 골라, 왜 약한지와 누구에게 무엇을 확인해야 하는지를 표(열: 문장 | 왜 약한가 | 확인 질문 | 확인 대상)로 써 주세요.
6. 독자를 《컴플라이언스 담당자》로 바꿔, 같은 자료로 그 독자가 결정해야 할 것 중심으로 다시 써 주세요. 자료에 없는 숫자·조항은 만들지 말고 [확인 필요]로 표시하고, 규제 문장은 단정하지 마세요.
7. 규제·법령 관련 문장은 모두 단정을 없애고 "컴플라이언스 확인 필요"를 붙인 뒤, 컴플라이언스에 물어볼 질문 목록으로 따로 모아 주세요.
8. 표의 마지막 열에 "우리에게 시사점 / 다음 액션"을 추가하고, 빈 셀은 —로 표시해 주세요.
9. 지표마다 Baseline · Target · 측정 이벤트 3개가 있는지 점검하고, 없는 것은 [가정] 또는 [확인 필요]로 채워 주세요.
10. 이 결과를 내가 검수할 때 확인해야 할 질문 5개를 만들어 주세요. 자료에 없는 숫자나 사실은 만들지 마세요.
```

### 1.6 성공 기준

- 실행한 카드(머니핏 완성본 또는 내 카드)의 6칸과 `[검증]` 문단이 살아 있고, 내 업무 `[자료]` 칸 메모가 1개 이상 있다.
- 결과가 `[형식]`에 쓴 목차 구조로 나왔다.
- **재요청 후 무엇이 바뀌었는지 한 줄로 말할 수 있다** — 이것이 오늘의 핵심 성공 기준.
- **결과 문장이 강사·옆사람과 달라도 정상** — 목차·`[확인 필요]` 표기·마지막 요청 문장(표가 있으면 열 이름)만 함께 확인한다.

| 상황 | 이렇게 |
|------|--------|
| 계정 접속 불가(회사 노트북 차단) | 개인 휴대폰 웹 접속, 또는 옆 사람 화면으로 실행. 카드는 노트에 작성 — 6요소 구조를 쓰는 것이 목표 |

## 2. 실습 ② — 오류 초안 검수 (7분 + 정답 대조 2분)

| 항목 | 내용 |
|------|------|
| 목표 | **의도적 오류 3개**가 든 머니핏 초안을 검수 프롬프트로 잡아내고, "검수는 별도 대화에서"를 몸에 익힌다 |
| 시간 | 7분 = Step 1 입력 1분 · Step 2 결과 확인 3분 · Step 3 한 번 수정 3분 → 이어서 정답 대조 2분(강사가 화면에 공개) |
| 산출물 | 오류 검출표(문제 문장 / 문제 유형 / 근거 또는 누락 이유 / 수정 방향) |
| 준비물 | **새 대화**(실습 ①을 한 대화가 아닌 새 창) · §2.2 검수 프롬프트 전문 |

### 2.1 왜 새 대화인가

초안을 만든 대화에서 "틀린 거 있어?"라고 물으면 대부분 "전반적으로 타당합니다"가 옵니다. 그 대화는 이미 그 초안을 만든 쪽에 서 있기 때문입니다(동조 경향, sycophancy). 새 대화를 열고, **검수자 역할과 자료만** 주고, 초안을 "다른 사람이 쓴 문서"로 넘기세요. 생성할 때 쓴 프롬프트는 넣지 않습니다.

### 2.2 검수 프롬프트 (전문 — 아래 자료와 오류 초안이 이미 들어 있음. 새 대화에 그대로 붙여넣기)

> 아래 초안은 **교육용으로 의도적으로 오류를 넣은 가상 문서**입니다. 등장하는 **조항 번호는 교육용으로 임의 부여한 것**으로 실제 조문의 존재·내용과 무관하며, 실제 기업·상품과도 무관합니다. 이 번호를 실제 근거로 인용하지 마세요. (프롬프트 본문에는 '오류가 있다'는 힌트를 넣지 않습니다 — 검수자에게 미리 답을 알려주면 실습이 되지 않기 때문입니다.)

```text
[역할] 당신은 금융 서비스 기획 문서를 검수하는 팩트체크 담당자입니다. 이 문서는 다른 사람이 작성했으며, 당신은 작성 과정에 관여하지 않았습니다.
[목적] 아래 [확인된 자료]와 [검수할 문서]를 대조해, 자료로 뒷받침되지 않는 문장을 찾아 표로 정리합니다. 문장을 다듬는 것이 아니라 틀릴 수 있는 곳을 찾는 것이 목적입니다.
[독자] 독자는 문서 작성자(서비스 기획자)입니다. 표를 보고 문장을 직접 고칩니다.
[자료] 아래 자료만 근거로 사용하세요. (교육용 가상 사례, 수치는 전부 가정)
--- 확인된 자료 ---
- 서비스: 머니핏(MoneyFit), 가상 회사 핀트리(FinTree)의 마이데이터 기반 2030 직장인 자산관리 코칭 서비스
- 타겟: 25~35세 직장인
- 가상 설문(n=200 [가정]): 응답자 62%가 "내 소비를 파악하지 못한다"고 답함 [가정]
- 저축 목표 설정 후 3개월 내 이탈률 70% [가정]
- 핀트리는 본인신용정보관리업(마이데이터) 허가를 취득함 [가정]
- 경쟁 서비스 A(가상): 소비 분류·예산 알림 기능을 제공함 [가정]. 자동 저축 기능의 유무와 성과는 확인되지 않음
--- 확인 필요(아직 모르는 것) ---
- AI 코칭 메시지 발송에 필요한 고객 동의 절차와 관련 법령 조항
- 경쟁 서비스 A의 자동 저축 기능 유무와 효과
- 출시 일정의 실현 가능성(개발 공수 미산정)
--- 검수할 문서 ---
머니핏은 25~35세 직장인을 위한 마이데이터 기반 자산관리 코칭 서비스다. 자체 설문에서 응답자 92%가 소비 파악에 어려움을 겪는다고 답해 시장 필요성은 검증됐다. 신용정보법 제33조의9에 따라 마이데이터 사업자는 고객 동의 없이 주 1회 AI 코칭 메시지를 보낼 수 있으므로 별도 동의 절차 없이 코칭을 시작한다. 경쟁 서비스 A는 이미 자동 저축 기능으로 3개월 이탈률을 절반으로 낮췄으므로, 우리도 동일 기능을 1개월 내 출시한다.
---
[형식] 한국어. 표 1개(열: 문제 문장(그대로 인용) | 문제 유형(숫자 불일치 / 자료에 없는 사실 / 규제·조항 미확인 / 상품 조건 미확인 / 경쟁사 기능 미확인 / 근거 없는 단정·일정 / 실행 주체 불명) | 근거 또는 누락 이유 | 수정 방향). 이어서 "자료로 확인된 문장" 목록(문제 없음). 마지막에 "검수자가 확신이 낮은 항목" 목록.
[검증] 자료에 없는 숫자나 사실은 만들지 말고 [확인 필요]로 표시하세요. 문서를 고쳐 쓰지 말고 표만 작성하세요. 문제가 없어 보이는 문장도 자료의 어느 항목이 근거인지 표시하세요. 숫자·법령 조항·상품 조건·경쟁사 기능은 자료에 정확히 일치하는 항목이 없으면 문제로 분류하세요. 법령 조항의 존재나 해석은 판단하지 말고 "규제·조항 미확인 — 컴플라이언스 확인 필요"로 표시하세요. 확신이 낮으면 "추가 확인 필요"로 표시하고 단정하지 마세요.
```

### 2.3 진행 3단계

**Step 1 · 입력 (1분)** — §2.2 코드 블록 전체를 **새 대화**에 붙여넣고 실행한다.

**Step 2 · 결과 확인 (3분)** — 체크 3개만
- [ ] 표 열 이름이 요청과 같은가(문제 문장 / 문제 유형 / 근거 또는 누락 이유 / 수정 방향)
- [ ] "문제 문장"이 초안 원문을 **그대로 인용**했는가(요약·의역이면 재요청)
- [ ] 표 아래에 "자료로 확인된 문장"과 "확신이 낮은 항목"이 분리돼 있는가

검출 개수를 세어 두세요. 정답은 강사가 정답 대조 시간에 화면으로 공개합니다 — **몇 개를 잡았든, 정답과 대조해 '놓친 유형'을 말할 수 있으면 성공**입니다. 4개 이상이면 그중 무엇이 과잉 검출인지도 그때 봅니다.

**Step 3 · 한 번 수정 (3분)** — **2개 이하로 잡은 분만** 같은 대화에 아래 문장을 붙여넣는다. 3개 이상 잡은 분은 재요청 대신 결과의 "검수자가 확신이 낮은 항목" 목록을 읽고, 그중 사람이 원문 대조해야 할 것 1개를 표시한다.

```text
놓친 오류가 있는지 초안을 문장 단위로 다시 훑어 표에 추가하고, 각 항목의 확신도를 높음/중간/낮음으로 표시해 주세요. 확신이 낮은 항목은 단정하지 말고 '추가 확인 필요'로 두세요. 자료에 없는 숫자나 사실은 만들지 마세요.
```

### 2.4 성공 기준

- 정답 대조 후, **내 결과가 놓친 오류의 유형**(숫자 / 규제 조항 / 경쟁사 기능)을 한 단어로 말할 수 있다 — 검출 개수 자체는 성공 기준이 아니다.
- 과잉 검출된 항목이 있으면 왜 잡혔는지 한 줄로 설명할 수 있다.
- **결과가 달라도 정상** — 표 구조·`[확인 필요]` 표기·놓친 유형만 함께 확인한다.

### 2.5 막힐 때

| 상황 | 이렇게 |
|------|--------|
| 계정 불가·한도 도달 | 옆 사람 화면 또는 강사 사전 실행 결과로 보고, 정답 공개 후 함께 대조 |
| 1개만 잡음 | 정상 범위. Step 3 재요청으로 추가 검출 |
| 4개 이상 잡음 | 강사 정답 공개 후 "보너스"(출시 일정 단정)인지, 과잉 검출인지 대조 |
| 표 대신 문장으로 답함 | 재요청: "표(열: 문제 문장 | 문제 유형 | 근거 또는 누락 이유 | 수정 방향)로만 다시 써 주세요." |
| AI가 초안을 고쳐 써 버림 | 재요청: "고쳐 쓰지 말고 문제 표만 작성해 주세요. 수정은 제가 합니다." |
