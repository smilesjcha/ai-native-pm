## 결론부터

> **"도구는 6개월마다 바뀌고 기준은 남는다."** 이 문서의 어느 셀도 '이 도구가 최고'라고 말하지 않는다. 각 셀은 **(1) 이 강의에서 어떤 역할인가, (2) 어느 모듈에서 강점이 드러나는가, (3) 금융권 환경 3층 중 어디서 쓸 수 있는가, (4) 강의 전에 무엇을 확인해야 하는가** — 네 가지만 답한다. 기능·요금·한도 숫자는 단정하지 않고 전부 `[강의 전 확인]`으로 남긴다.

**이 강의의 도구 운영 결정 (00-review-checklist A3 확정 기준)**

| 구분 | 결정 | 왜 |
|------|------|----|
| 수강생 실습 | **무료 웹 3종(ChatGPT·Claude·Gemini) 중 택1** + 두 번째 도구 1개(한도 폴백) · 복사·붙여넣기만 · 코딩·설치·계정 연동 없음 | 커리큘럼이 3사 비교를 명시하고, 회사마다 허용 도구가 달라 통일이 불가능하다. 프롬프트 카드(요청 6요소)는 도구 독립적이므로 어느 도구에서도 같은 실습이 성립한다 |
| 강사 시연 | **Claude 웹(수강생 시점 무료 프로필) 중심** + 비교가 필요한 장면만 3사 화면 병렬(M1 옵트아웃 설정, M5 딥 리서치(Deep Research, 심층 리서치)) | 하루 종일 한 도구 화면을 유지해야 수강생이 "도구가 아니라 요청 구조"를 본다. 강사 경험상 긴 문서 초안·구조 지정 요청에서 결과 형식이 안정적이라 시연 기본 도구로 택했다(우열 주장이 아님) |
| 유료·확장 | **강사 시연 + 가져가기 플레이북(§4 4단계 로드맵)** 으로만 다룬다. Deep Research · Claude Desktop(Cowork·Skills·커넥터) · Claude Code · Claude for PowerPoint · Codex | 수강생 실습에 넣으면 계정·설치·보안 승인 세 가지가 동시에 막힌다. 대신 "회사에서 어떤 순서로 열어가는가"를 들고 가게 한다 |

## 1. 도구 × 상태 매트릭스

> 읽는 법: **역할** = 수강생 실습(L) / 강사 시연(D) / 가져가기(T, 회사에서 다음 단계). **환경 3층** = 1층 개인 계정(가상·공개 자료만) / 2층 회사 승인 계정(내부 가이드 범위) / 3층 응용 프로그램 인터페이스(Application Programming Interface, API)·사내 구축(개발·보안 협업, 오늘 범위 외). 각 셀의 기능·플랜·한도는 2026-09 기준으로 강사가 각 사 공식 안내에서 확인해 채운다. 미확인 셀은 "확인 중"으로 두고 조건문으로 말한다.

## 2. 커리큘럼 용도별 도구 선택표

> 열 순서가 곧 발화 순서다: **오늘 실습(무료 웹)** → **강사 시연** → **가져가기(회사)** → **선택 기준(왜)**. "어느 도구가 좋냐"에는 항상 네 번째 열로 답한다.

| 용도 | 오늘 실습(수강생 · 무료 웹 택1) | 강사 시연 | 가져가기(회사에서) | 선택 기준 — 왜 | `[강의 전 확인]` |
|------|------------------------------|----------|-------------------|---------------|----------------|

## 3. 단계별 사용 전략 — 4단계 로드맵 (가져가기 플레이북)

> 발전 6단계(01 §3 원칙 6 · lab-3 §E)를 **회사에서 실행 가능한 4단계**로 접은 것이다. 대응: 1단계 = 6단계의 ①Chat·②문서 생성 / 2단계 = ③템플릿화 / 3단계 = ④연결(모델 컨텍스트 프로토콜(Model Context Protocol, MCP)·커넥터)·⑤오피스 내장 / 4단계 = ⑥Agentic. 위 단계가 더 좋은 것이 아니다 — **반복 횟수·파일 수·승인 환경** 세 조건이 맞을 때 올라간다.

## 7. `[강의 전 확인]` 집계

이 문서의 `[강의 전 확인]` 태그는 **셀 단위 묶음**이다(한 태그 아래 여러 항목). 강의 전 확인 작업은 08-prep-checklist의 "`[강의 전 확인]` 셀 채우기" 항목으로 수행하고, 확인된 셀은 04 §M1 보조표에 먼저 채운 뒤 이 문서의 해당 셀을 "확인됨(2026-09-19 기준)"으로 바꾼다. 확인 못 한 셀은 삭제하지 않고 "확인 중 → 회사에 물을 항목"으로 남긴다 — 결함이 아니라 수강생이 가져갈 질문 목록이기 때문이다.

| 절 | 항목 태그 수 | 주된 내용 |
|----|------------:|----------|
| §1 도구 × 상태 매트릭스 | 14 | 3사 × 상태별 플랜·한도·기능 명칭·설정 경로(11셀) + 참고 도구 4종(4셀) — 셀 14개, 각 셀 안에 3~5개 세부 항목 |

| §4 제약 대응표 | 2 | 옵트아웃 제공 여부·메뉴 경로(Gemini 방식 포함), 기업 플랜 약정 항목 |
| §5 전환 시나리오 | 1 | 3사 한도 도달 안내 문구·축소 모델 전환 표시 |
