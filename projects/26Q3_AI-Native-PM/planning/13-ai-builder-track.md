## 결론부터

> **기획자가 Figma 없이도 디자인 토큰 → 코드 시안 → 동작 프로토타입 → 데모 영상까지 만들어 PRD에 임베드하면, 디자이너·개발자·임원이 "질문 없이" 이해한다. 오늘은 시연 + 가져가기 플레이북이다.**

- 실습이 아니라 **시연**이다. 수강생 실습 기준(무료 웹 계정·복사·붙여넣기·코딩 금지)을 지키기 위해, 오늘 강의에서는 Lv1(무료 웹에서 단일 HTML 시안 1장)만 **미니 체험(선택)** 으로 열고, Lv3(Claude Code로 캡처·영상 자동화)는 강사가 사전 제작 에셋으로 보여준다.
- 이 문서를 위해 러닝 케이스 머니핏의 **실제 에셋 9개**(시안 보드 PNG · 프로토타입 화면 PNG 5 · 데모 MP4 · poster · 퍼널 차트 PNG)를 만들어 `assets/builder/`에 두었다. 전부 교육용 가상 사례이고, 재생성 명령은 README에 있다. 실패한 단계는 없으며, `shoot.js`의 쿼리스트링 미지원은 인라인 스크립트로 우회했고 그대로 기록했다.
- 장표 삽입 제안은 §8 — 본문 3장(M6·M11·M12) + 부록 7장. 슬라이드 예산(약 95장)을 지키기 위해 본문 추가는 3장으로 제한하고, 나머지는 발표 시 건너뛰는 부록으로 둔다(결정은 `00-review-checklist.md`에 추가 제안, §9).

## 1. 왜 코드 시안인가 — Figma 대비, 정직하게

| 관점 | 코드 시안(HTML + 디자인 토큰) | Figma 등 디자인 도구 | 이 강의의 판단 |
|------|-----------------------------|-------------------|---------------|
| 토큰 일관성 | 토큰이 곧 CSS 변수(`--color-action-blue`). 시안·프로토타입·차트가 같은 값 | 스타일·변수 기능으로 가능하지만 사람이 지켜야 한다 | 기획자가 혼자 만들 때는 코드가 덜 틀어진다 |
| 갱신 속도 | 문구 한 줄 고치고 명령 1개로 재캡처. 이번 제작에서 막대 버그 수정 → 재캡처가 2분 | 수정 → 내보내기 → 문서에 다시 붙이기 | PRD가 살아 있으려면 "고치면 바로 갱신"이 필요 |
| PRD 임베드 | PNG·MP4를 상대경로로 같은 폴더에 둔다 → GitHub·VS Code·위키 어디서나 보인다 | 링크 임베드(권한·로그인 필요할 수 있음 `[확인 필요]`) | 문서 독자가 로그인 없이 봐야 한다 |
| 데모 영상 | `?demo=1` 자동 재생 → 녹화 → 27초 MP4. 임원 보고 6장(동작 방식)에 바로 | 프로토타입 화면 녹화는 가능하나 자동 재생·재녹화 파이프라인은 별도 | 영상은 임원에게 가장 강한 무기(§4) |
| 비용·환경 | Lv1은 무료 웹 채팅으로 가능. 로컬 HTML 파일은 **서버 업로드 없이** 열린다 | 유료 플랜·외부 SaaS 접속 필요할 수 있음 `[강의 전 확인]` | 금융권 망분리 환경에서 로컬 파일이 갖는 장점(§6) |
| **한계** | 정교한 비주얼·아이콘·일러스트 약함 / 디자이너 협업 코멘트·버전 UI 없음 / 픽셀 단위 조정은 코드로 / 접근성 검토 도구 없음 | 디자이너의 표준 도구, 컴포넌트 라이브러리, 핸드오프(Dev Mode 등 `[강의 전 확인]`) | **코드 시안은 디자이너를 대체하지 않는다.** 디자이너 착수 전 "무엇을 만들지"를 합의하는 도구다 |

**노하우(왜)**: 금융권에서 AI를 4년 넣으면서 배운 것은 "외부에 올릴 수 없는 환경"이 디자인 도구에도 똑같이 걸린다는 점이다. 로컬 HTML 한 파일은 그 제약 안에서도 열리고, 시안 문구를 고친 뒤 재캡처가 명령 하나라서 PRD의 그림이 낡지 않는다. 커머스에서 에이전트 기획을 하면서는, 문서에 프로토타입이 붙어 있으면 개발 킥오프의 질문이 "이 버튼 누르면 어디로 가요"에서 "이벤트 파라미터를 뭘로 잡을까요"로 바뀌는 것을 반복해서 봤다. 질문의 수준이 올라가는 것이 정렬이다.

## 2. 5단계 파이프라인 — 도구 레벨 · 프롬프트 · 산출물 · 소요 · 흔한 실패

```
① 디자인 토큰 확보 ──► ② 지면별 AI 매트릭스 ──► ③ 코드 시안(HTML→PNG) ──► ④ 동작 프로토타입(상태기계·?demo=1) ──► ⑤ 데모 영상(MP4)
      DESIGN.md → :root 변수        지면×AI×이벤트 표             파란 박스 = AI 적용 지점             클릭 전환·이벤트 배지                    녹화 → PRD 임베드 → 정렬(디자이너/개발/임원)
```

**도구 레벨 정의** — Lv1 무료 웹 채팅(ChatGPT·Claude·Gemini 택1, 붙여넣기만) · Lv2 데스크톱 앱(Claude Desktop 등)에서 파일 저장·수정 `[강의 전 확인]` · Lv3 터미널 에이전트(Claude Code 등)가 파일·명령까지 실행 `[강의 전 확인]`. 아래 소요는 **이 문서의 에셋을 Claude Code로 만든 1회 실측**(HTML 2개·캡처·녹화·차트 = 약 40분, 수정 2회 포함)과 Lv1 추정 `[가정]`이다.

| 단계 | Lv1 무료 웹으로 되는 것 | Lv2 Claude Desktop | Lv3 Claude Code | 산출물 | 소요 | 흔한 실패(→ 대응) |
|------|----------------------|-------------------|-----------------|--------|-----:|------------------|
| ① 디자인 토큰 확보 | DESIGN.md·tokens.css 전문을 붙여 토큰 표 + `:root` 변수 블록 받기 | 파일을 열어 읽게 하고 `tokens.css`로 저장 | `tokens.json/css/js` + `style-guide.html` 생성·캡처 | 토큰 표·CSS 변수 블록 | Lv1 5분 / Lv3 10분 [가정] | AI가 없는 색을 추가·두 번째 액센트 생성 → "자료에 있는 값만", 액센트 1개 규칙 |

| ④ 동작 프로토타입 | 상태기계 표 → 단일 HTML → 미리보기에서 클릭 체험 | 파일 저장·브라우저 테스트 | `?screen=N` 캡처 5장 자동 | `prototype/index.html` → `moneyfit-proto-01~05.png` | Lv1 15–20분 / Lv3 15분 | 버튼이 연결 안 됨(`data-go` 오타) · 상태 수 폭발 · 자동 데모 커서가 숨은 요소를 클릭 · 로딩 타이머와 클릭 충돌 → 상태기계 표를 먼저 고정 |
| ⑤ 데모 영상 | (불가 — 화면 녹화 앱으로 수동) | 수동 녹화 | `record-proto.js`로 `?demo=1` 녹화 → ffmpeg MP4 + poster | `moneyfit-demo.mp4`(27.5초) · poster | Lv3 5분(설치 제외) | Playwright ffmpeg 없음 → `npx playwright install ffmpeg` · 종료 플래그 `__DEMO_DONE__` 누락 → 40초 타임아웃 · `shoot.js` 쿼리 미지원 → 인라인 스크립트(README §3-3) |

### 2-1. 단계별 프롬프트 전문 (머니핏) — 단일 원본은 `workshop/builder/prompts.md`, 아래는 동일 내용

모든 프롬프트 앞에 **P-B0 공통 규칙 블록**을 붙인다(가상 사례·[가정]·컴플라이언스 표기·존재하지 않는 기능 금지). 카드 번호는 prompts.md와 같다.

```text
[공통 규칙]
- 이 작업은 교육용 가상 사례 "머니핏(MoneyFit) — 가상 회사 핀트리(FinTree)의 마이데이터 기반 2030 직장인 자산관리 코칭 앱"을 대상으로 한다. 실제 금융기관·금융상품·인물·고객 정보를 화면이나 문서에 넣지 않는다. 기관명은 "은행 A·카드사 B"처럼 가상 표기만 쓴다.
- 화면에 들어가는 모든 숫자(금액·비율·기간)는 예시이며 뒤에 [가정]을 붙인다. 자료에 없는 사실을 만들지 않고, 모르면 [확인 필요]로 남긴다.
- 인증·동의·금융상품 안내 문구는 초안이며 "컴플라이언스 확인 필요"를 화면 또는 주석에 표시한다. 투자·상품 권유로 읽히는 문장은 쓰지 않는다.

- 존재하지 않는 도구 기능·법령·규정을 만들지 않는다. 규제를 언급하면 "기관·문서명·연도 + [확인 필요]" 형식으로 쓴다.
```

```text
[역할] 당신은 디자인 시스템 토큰을 정리하는 프런트엔드 디자이너입니다. 값을 새로 만들지 않고 자료에 있는 값만 옮깁니다.

3) 표 아래 "Do / Don't" 각 3줄 — 액센트 색은 하나만, 두 번째 브랜드색 금지, 그림자는 제품 이미지에만 같은 원칙을 자료에서 찾아 옮깁니다(자료에 없으면 [확인 필요]).

[검증]
- 자료에 없는 색·수치를 추가하지 않습니다. 추가가 필요하면 값 대신 "[확인 필요]"를 씁니다.
- 액센트 색이 2개 이상 뽑혔으면 하나로 줄이고 이유를 한 줄 씁니다.
- 마지막에 "이 토큰으로 못 그리는 것 2개"를 씁니다(예: 차트 색 단계, 상태 색).
---
[여기에 DESIGN.md 전문 또는 docs/design-system/tokens/tokens.css 전문 붙이기]
```
