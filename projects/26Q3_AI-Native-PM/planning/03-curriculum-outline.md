## 결론부터

- 3세션 × 100분 = **13개 모듈**. 각 모듈은 `핵심 메시지 1문장 → 강의 → 시연 → 실습(입력→확인→한 번 수정) → 회수` 구조.
- 수강생 산출물 **3개 + 1장**: ① 프롬프트 템플릿 카드 ② PRD 초안+AI 리뷰+2-Pager ③ 분석·회의록·슬라이드 아웃라인 중 1개 + 나의 자동화 워크플로 1장.
- 슬라이드 예산 **약 95장(±10)**. 실습 장표는 "프롬프트 그대로 붙여넣기" 형태로 만들어 PDF만 보고도 재현 가능하게 한다.


### M1. 생성형 AI 도구 지도 — 우열이 아니라 선택 기준 (09:40–10:05 · 25분 · ~8장)

| 항목 | 내용 |
|------|------|
| 핵심 메시지 | "회사가 허용한 도구 안에서, 업무 유형에 맞게 고르는 기준이 중요하다." |
| 내용 | ① 3사 비교표 — 기준 8행(무료 플랜 범위·긴 문서 처리·파일 분석·웹 검색/Deep Research(심층 리서치)·오피스 연동·맞춤 도구(GPTs·Projects/Skills·Gems)·데이터 학습 정책(옵트아웃)·기업용 플랜), 각 셀은 "확인할 것" `[강의 전 확인]` ② 기획자 업무 유형별 추천 매핑(리서치·장문 작성·오피스 연동·데이터 분석·발표·회의) ③ **금융권 사용 환경 3층**(개인 계정 / 회사 승인 계정 / API·사내 구축) + 망분리 개선·생성형 AI 활용 가이드 동향 `[확인 필요, 출처 표기]` ④ 데이터 학습 옵트아웃 설정 화면 시연 ⑤ 커리큘럼 연결: 온라인 M7(클로드 코워크·스킬·커넥터) 예고 |
| 노하우 | "어느 도구가 최고냐"는 질문에 답하지 말고 "이 업무엔 이 기준으로 이 도구"로 바꿔 답한다. 도구는 6개월마다 바뀌지만 기준은 남는다 |
| 활동 | 1분 체크: 내가 지금 쓸 수 있는 환경(개인/회사/둘 다) + 오늘 실습에 쓸 도구 1개 선택 |
| 상세 | §M1 |

### M2. 프롬프트 설계 원칙과 금융 도메인 템플릿 — 요청 6요소 (10:05–10:50 · 45분 · ~14장)

| 항목 | 내용 |
|------|------|
| 핵심 메시지 | "좋은 프롬프트는 잘 쓴 질문이 아니라, 잘 정의된 업무 요청서다." |
| 강의(15분) | ① 커리큘럼 4요소(역할·맥락·제약·출력 형식) → 실무 **요청 6요소(역할·목적·독자·자료·형식·검증)** — 금융의 차이는 '검증' ② 나쁜 vs 좋은 프롬프트(금융 사례: "마이데이터 서비스 기획서 써줘" vs 6요소 버전) ③ 기법 4개(쿠션어 제거·부정→긍정·구분자·역할 부여) + 3개(예시 제공·단계 분할·형식 강제) ④ 자주 하는 실수 3가지(한 번에 다 요청·자료 없이 요청·첫 답 그대로 사용) ⑤ **금융 도메인 템플릿 3종** — (a) 서비스·상품 기획 초안 (b) 규제·약관 검토 보조(원문 대조·컴플라이언스 확인 문구 내장) (c) 데이터 해석·보고(M4 연결) |
| 시연(5분) | 템플릿 (a)로 머니핏 기획 초안 요청 → 결과 → 재요청 문장 1개로 수정 |
| **실습 ①(15분)** | 기본 경로: 머니핏 완성본(lab-1 §1.3)을 새 대화에 그대로 실행(3분, 대기 중 빈 카드의 **[자료] 칸만 내 업무로 메모**) → 결과 확인 3개(목차·[확인 필요]·마지막 요청 문장, 4분) → "재요청 문장 10선" 중 1개로 한 번 수정(5분) → 카드 v1 저장(1.5분). 내 업무 카드 6칸 완성은 11:10 캐치업, [자료] 메모는 오후 기획서 실습 Step 1의 5개 핵심 입력(= 카드 v2)으로 이월. ⚠ 검수 후 변경 — 원안(내 업무 6칸을 15분에 작성)은 초보자에게 비현실적이라는 교수설계 검수 결과. 결정 대기: `00-review-checklist` **E5** |
| 공유(10분) | 페어 체크 3분(6요소·검증 조건·실데이터 없음) → 강사 화면 공유 2명(각 2분, 강사 노트북에 붙여넣기) → 버퍼 1분 → 카드 파일 저장 |
| 노하우 | "프롬프트는 문서다" — 카드로 저장·v1/v2 버전 관리. 재요청 문장 10개를 외우면 첫 답의 품질에 덜 좌우된다 |
| 산출물 | **① 프롬프트 템플릿 카드 v1**(머니핏 완성본 실행·재요청 결과 + 내 업무 [자료] 메모) — 실습 ②의 오류 초안 검수 결과와 함께 저장 |
| 상세 | §M2 · 실습 가이드 [`../workshop/lab-1-prompt-design.md`](../workshop/lab-1-prompt-design.md) · 템플릿 [`../workshop/prompt-templates-fintech.md`](../workshop/prompt-templates-fintech.md) |

### M3. 환각 방지와 팩트체크 — 금융에서 위험한 4곳 (10:50–11:10 · 20분 · ~7장)

| 항목 | 내용 |
|------|------|

| 강의(8분) | ① 금융에서 환각이 위험한 4곳: 숫자(금리·수수료·시장규모), 규제·법령 조항, 상품 조건·약관, 경쟁사 기능(존재하지 않는 기능) ② 환각 대응 3원칙(근거 요청·확인 필요 표시·원문 대조) + 금융 확장 4개(출처 URL·기준일 요구 / 1차 자료 우선: 금융위·금감원·한국은행·공시 / 자기 비판(self-critique) 요청 / 두 모델 교차 검증·숫자 재계산) ③ 검증 프롬프트 템플릿 |

| 노하우 | 검수는 별도 대화(fresh context)에서 시킨다. 같은 대화에서 "맞지?"라고 물으면 동조한다 |

### M5. AI 리서치 — 시장 분석 보고서와 경쟁사 벤치마킹 자동화 (12:40–13:05 · 25분 · ~7장)

| 항목 | 내용 |
|------|------|
| 핵심 메시지 | "리서치는 검색이 아니라 질문 설계다. 출처 없는 문장은 삭제한다." |
| 강의(10분) | ① 리서치 3단계(리서치 브리프 → Deep Research 실행 → 출처 검증·표 정리) ② **리서치 브리프 템플릿**(목적·핵심 질문 5개·범위·기간·제외·출력 형식·출처 요건) ③ 결과는 **5열 표**(주장·근거·출처·기준일·신뢰도)로 받는다 ④ 1차 자료 vs 2차 자료 ⑤ 경쟁사 벤치마킹 자동화: 비교 관점 정의(기능·타겟·가격·UX 강점·AI 활용·규제 대응) → 표 생성 → **"존재 확인" 열** 추가 → 스프레드시트 |
| 시연(7분) | Deep Research 1회(사전 실행 결과 백업) — 머니핏 시장 규모·경쟁 서비스 → 출처 클릭 검증 1개 |
| 미니 실습(8분) | 경쟁 서비스 3개 벤치마크 표 생성 → 출처 1개 직접 확인 → "존재 확인" 열 채우기 |
| 노하우 | 시장 규모 수치는 "출처·기준일·산정 방식" 없으면 보고서에 넣지 않는다. 벤치마킹 표의 마지막 열은 항상 "우리에게 시사점" |
| 상세 | §M5 |

### M6. 기획서 구조화 원칙 — 읽히는 기획서 (13:05–13:25 · 20분 · ~6장)

| 항목 | 내용 |
|------|------|
| 핵심 메시지 | "AI가 채우기 전에 사람이 뼈대(5개 입력·섹션·지표)를 정한다." |
| 내용 | ① 문서 계층(2-Pager 왜 → PRD 무엇 → Spec/HLD 어떻게 → ADR → Ops) — M3 PRD와 연결 ② PRD 핵심 섹션 + 5개 핵심 입력으로 AI가 나머지를 채우는 구조 ③ **잘 읽히는 기획서 노하우 4**: 두괄식(BLUF)·중복 제거·표 양식(첫 열=기준, 끝 열=액션)·지표 3종(Baseline→Target→측정) ④ **금융 기획서 필수 섹션: 규제·리스크 체크**(개인정보·신용정보·전자금융·금소법 — 컴플라이언스 질문 목록으로) ⑤ 기획서(대내) vs 제안서(대외) 1장 ⑥ **AI로 쓰고 AI로 평가받기** — 3관점(리더십·디자이너·EM) 리뷰 프롬프트, 사람이 결정 |
| 노하우 | 섹션 제목을 결론형 문장으로("문제: 결정 근거 부족이 이탈을 만든다"). 표와 본문이 같은 말을 하면 표만 남긴다 |
| 상세 | §M6 · 근거 `docs/guides/prd-authoring-playbook.md` |

### M7. 실습 ③ — AI로 핀테크 서비스 기획서 작성 (13:25–14:00 · 35분 · ~8장 + 부록 A1–A3 프롬프트 전문 3장, 발표 시 건너뜀)

| 스텝 | 분 | 내용 | 확인 포인트 |
|------|---:|------|------------|
| 1 입력 | 5 | 5개 핵심 입력 작성(머니핏 or 내 서비스) | 성공 기준에 숫자 후보가 있나(`[가정]` 허용) |
