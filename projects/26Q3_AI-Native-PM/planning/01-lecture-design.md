## 결론부터

> **"도구를 많이 보여주는 날"이 아니라, "월요일에 내 업무 하나를 AI와 다르게 하는 방법을 손에 들고 가는 날"이다.**
> 하나의 가상 핀테크 사례(머니핏)를 프롬프트 → 리서치 → 기획서 → 데이터 → 회의록 → 슬라이드 → 워크플로까지 **끊김 없이 한 번에** 다루고, 수강생은 각 세션에서 **산출물 1개씩(총 3개 + 워크플로 1장)** 을 자기 업무로 만든다.
> 금융권 특성상 **보안·환각 검증을 기법이 아닌 습관**으로 앞에 배치한다.

| 도구 3종 비교가 명시된 커리큘럼 | 도구 우열이 아니라 **"내 회사에서 쓸 수 있는 도구 안에서 선택하는 기준"** 으로 다룬다 |

## 3. 설계 원칙 6가지

1. **One spine, fully worked** — 러닝 케이스 하나(머니핏)를 하루 종일 이어간다. 새 예시를 흩뿌리지 않는다. (근거: `projects/26Q2_Fastcampus-Lecture/planning/teaching-design-direction.md`)
2. **산출물 중심** — 세션마다 "손에 들고 가는 것"을 첫 장에 선언하고 마지막 장에 회수한다. 완성도가 아니라 **"요청 구조를 고쳐 다시 받는 경험"** 에 학습 초점.
3. **보안·검증 선행** — 금융권이므로 "입력 전 30초 체크리스트(사람·회사·고객·권한)"와 "환각 3원칙(근거 요청·확인 필요 표시·원문 대조)"을 도구 사용법보다 먼저 가르치고, 이후 모든 실습 프롬프트에 검증 조건을 내장한다.
4. **요청 6요소 하나로 하루를 관통** — 역할·목적·독자·자료·형식·검증. 커리큘럼의 "역할·맥락·제약·출력 형식"을 포함하는 상위 프레임. 프롬프트(S1) → 기획서(S2) → 분석·회의록·슬라이드(S3) 모두 같은 틀로 요청한다.
5. **AI로 쓰고, AI로 평가받고, 사람이 결정** — 초안 생성으로 끝내지 않고 3관점(리더십·디자이너·EM) AI 리뷰 → 보완 → 사람의 최종 판단을 실습 루프에 넣는다. (근거: `docs/evaluation/`, `docs/guides/stakeholder-alignment-playbook.md`)
6. **무료로 실습, 유료·확장은 발전 단계 서사로 시연** — "Chat → 문서 생성 → 템플릿화(Skills·GPTs·Gems) → 연결(MCP·커넥터) → 오피스 내장 → Agentic(Cowork·Claude Code)" 6단계로 소개하되 자랑이 아닌 **선택 기준**을 준다. (근거: `references/lecture-docs/how-to-work-better-worklife-ax-workshop/01-lecture-plan.md`)

## 4. 핵심 메시지 (세 문장)

1. AI는 기획자를 대체하지 않는다. **AI에게 "무엇을, 누구를 위해, 어떤 근거로, 어떻게 검증할지"를 정의하는 기획자**가 그렇지 않은 기획자를 대체한다.
2. 금융에서 생성형 AI의 가치는 속도가 아니라 **"검증 가능한 초안"** 이다. 근거·출처·확인 필요 표시가 없는 결과는 초안도 아니다.
3. 프롬프트는 문장이 아니라 **문서**다. 템플릿으로 저장하고, 버전을 매기고, 팀의 일하는 방식(규칙 파일)으로 키우는 것이 생산성이다.

## 5. 러닝 케이스 (교육용 가상 사례)

> ⚠️ 아래는 **전부 가상**이다. 실제 기업·상품·수치가 아니며, 강의 자료 어디에서도 사실처럼 쓰지 않는다. 명칭은 리뷰 체크리스트 §3에서 확정한다.

| 항목 | 내용 |
|------|------|
| 가상 회사 | **핀트리(FinTree)** — 시리즈 A 단계 핀테크 스타트업 (마이데이터 사업자 허가 취득 `[가정]`) |
| 서비스 | **머니핏(MoneyFit)** — 마이데이터 기반 2030 직장인 자산관리 코칭. 계좌·카드 연동 → 소비 자동 분류 → 월 예산·저축 목표 설정 → AI 코칭 메시지·목표 달성 시뮬레이션 |
| 타겟 | 25–35세 직장인, 급여는 있으나 계좌·카드가 분산되어 소비 파악이 어렵고 저축 목표를 세워도 3개월 내 이탈 `[가정]` |
| 문제 | "내 돈이 어디로 가는지 모른다" — 파악 비용(시간)과 실행 실패(자동화 부재). 수치는 실습에서 `[가정]`으로 채운다 |
| AI 활용점 | 거래 내역 카테고리 분류·요약, 소비 패턴 인사이트, 개인화 코칭 문구, 목표 시뮬레이션 설명, CS 자동 응대 |
| 성공 기준(예) | 첫 저축 목표 설정율, 자동 저축 실행율, 30일 리텐션 — Baseline→Target→측정 이벤트 3종 세트로 실습에서 정의 |
| 규제 체크(기획서 필수 섹션) | 본인신용정보관리업(마이데이터) 허가·전송요구권, 신용정보법·개인정보보호법(가명처리), 금융소비자보호법(투자 권유가 아닌 정보 제공 범위), 전자금융거래법 — **모두 "컴플라이언스 확인 필요" 표기**, 강의는 법률 자문이 아님 |
| 데이터(가상) | `workshop/sample-data/moneyfit-events.csv`(가입→연동→목표설정→첫 저축 퍼널 이벤트), `moneyfit-transactions.csv`(카테고리별 가상 거래), `moneyfit-kickoff-meeting-notes.md`(킥오프 회의 메모) |
| 하루 동선 | S1 프롬프트 템플릿(머니핏 기획 초안 요청) → S2 리서치(경쟁 서비스 벤치마크)·PRD·2-Pager → S3 이벤트 데이터 퍼널 분석·킥오프 회의록·임원 보고 슬라이드·이메일 → 워크플로 1장 |

**대안 후보** (리뷰 시 선택): (B) 소상공인 매출 데이터 기반 비대면 대출 사전심사 UX, (C) 간편결제 앱 구독·자동이체 관리 알림. 기본 권장은 (A) 머니핏 — M4 실습(마이데이터 기반 자산관리 기획안)과 연속되고 데이터 분석 실습과 자연스럽게 이어진다.

## 6. Core / Optional 큐레이션

| 블록 | 비중 | 이유 |

| 도구 3종 비교 | Core(간결, 표 1–2장) | 커리큘럼 명시. 우열 대신 선택 기준 |
| 환각·보안 | **Core** | 금융권 필수. 실습 ②로 체득 |
| Deep Research 시연 | Core(시연 1회) + Optional(심화) | 결과는 사전 실행본으로 백업 |
| 기획서(PRD) 실습 + 3관점 AI 리뷰 | **Core** | 이 강의의 심장. 35분 확보 |
| 제안서(대외) 구조 | Optional(1장) | 기획서와의 차이만 |
| 데이터 분석 따라하기 | Core(1회) | M4 연결. 가상 CSV 1개 |
| 회의록·이메일 | Core(짧게) | 가장 즉시 적용되는 생산성 |
| 슬라이드 생성 도구 시연 | Core(시연) + Optional(도구 비교) | 아웃라인은 실습, 생성은 시연 |
| 나의 하네스(폴더·템플릿·규칙 파일) | Core(1–2장) | 차별화 포인트. "프롬프트는 문서다"의 실체 |
| Cowork·Claude Code·MCP 시연 | Optional(발전 단계 서사) | 시간 부족 시 사전 녹화 30초로 대체 |

## 7. 이 강의에서 "안 다루는 것" (첫 장에 명시)

- API 연동·코딩·RAG 구축·파인튜닝 (개발자 과정 M6–M8, 온라인 M8·M9의 영역)
- Figma 프로토타이핑 실습(M3), 엑셀 수식·통계 실습(M4) — "AI로 연결"만 다룬다
- 특정 회사 내부 시스템 연동, 실데이터 분석
- 법률·규제 판단 — 규제 체크리스트는 "컴플라이언스에 무엇을 물어볼지"까지만
