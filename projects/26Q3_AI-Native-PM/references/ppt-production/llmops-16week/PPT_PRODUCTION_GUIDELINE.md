# LLMOps 강의 PPT 제작 가이드

이 문서는 Week 01뿐 아니라 16주 강의 자료에 공통 적용하는 제작 기준이다. 특정 브랜드의 화면을 복제하지 않고, 한국 패션 에디토리얼의 선명한 흑백 대비와 날카로운 그리드를 강의 정보 설계에 적용한다.

## 1. 콘텐츠 우선순위

1. 한 장에는 `개념·비교·근거·실행·평가` 가운데 한 역할만 둔다.
2. 장수 확보를 위한 문장 분할을 금지한다. 새 장표는 반례, 실제 화면, 코드 경계, 실패 복구, 새 판단 상황처럼 새로운 학습 역할을 가져야 한다.
3. 제목만 처음부터 끝까지 읽었을 때 논리가 앞으로 전진해야 한다.
4. 같은 결론을 제목·부제·첫 본문에서 반복하지 않는다.
5. 설명 배경과 교수자용 반례는 발표자 노트에 두고, 화면에는 이해·판단·실행·완료 확인에 필요한 내용만 남긴다.

## 2. 제목과 카피

- 표지 제목, 장표 제목, 부제는 짧은 명사형을 기본값으로 한다.
- 일반 제목은 2–8단어와 한 줄을 우선한다.
- `합니다`, `됩니다`, `있습니다`, `~다` 같은 문장형 종결어미와 마침표를 제목에 쓰지 않는다.
- 표지 부제는 설명 문장 대신 `기술 · 과업 · 산출물` 키워드 조합으로 구성한다.
- 파일명과 제작 메타데이터는 제목이 아니라 별도 label에 둔다.
- `정리`, `핵심 포인트`, `왜 중요한가`처럼 어디에나 붙는 제목은 구체적인 판단 대상으로 바꾼다.

기술 용어의 첫 등장은 `한글 용어(English full term, 약어)` 순서로 표기한다. 독립적으로 공유될 장표에서는 약어와 전체 용어를 같은 장표에 둔다. `CTX`, `EVAL`, `GOVERN`, `OBSERVE`, `ADAPT`처럼 임의로 줄인 레이블은 사용하지 않는다. 공간이 부족하면 단어를 자르지 말고 번호·용어·설명 영역을 분리한다.

## 3. 색상 정책

| Token | Hex | 용도 |
|---|---|---|
| `BLACK` | `#050505` | 표지, 강한 section, 주요 제목 |
| `INK` | `#191919` | 본문과 diagram |
| `WHITE` | `#FFFFFF` | 기본 배경과 dark surface 본문 |
| `PAPER` | `#F7F8FA` | 화면 호흡을 위한 밝은 surface |
| `NAVY` | `#0B1F3A` | section과 구조 강조 |
| `BLUE` | `#2563EB` | 현재 변수·운영 증거·평가 결과·운영 결정 |
| `BLUE_SOFT` | `#E0F0FE` | 약한 비교 면과 annotation |
| `GRAY` | `#667085` | 보조 본문 |
| `HAIRLINE` | `#D0D5DD` | 구분선 |

주황·빨강·노랑·초록·보라·시안, gradient, glow, glassmorphism을 자체 디자인에 사용하지 않는다. 외부 실제 화면·원본 사진·연구 도표가 원래 색을 포함하는 경우는 증거의 의미를 보존하기 위한 예외다. 원본 색을 임의로 바꿔 범례와 내용을 왜곡하지 않는다.

파랑은 순서나 위치가 아니라 의미로 사용한다.

- 허용: 현재 실험 변수, 관찰할 운영 증거, 평가 결과, 운영 결정, 실패 경로
- 금지: 마지막 항목, 오른쪽 열, 가장 큰 숫자, 마지막 슬라이드라는 이유의 자동 강조
- 같은 위계의 항목은 같은 색과 무게를 유지한다.

## 4. Typography 정책

PowerPoint/PDF에서 실제로 보이는 크기를 기준으로 검수한다.

| 요소 | 최소 | 권장 |
|---|---:|---:|
| 표지 제목 | 54pt | 58–64pt |
| Section 제목 | 44pt | 46–50pt |
| 일반 제목 | 38pt | 40–44pt |
| 중간 제목·핵심 수치 | 24pt | 26–32pt |
| 본문 | 18pt | 20–24pt |
| 표 Cell | 17pt | 18–20pt |
| Code | 16pt | 17–19pt |
| Micro label·footer·출처 | **14pt** | 14–16pt |

- 화면에 보이는 모든 텍스트의 절대 최소는 14pt다.
- `shrinkText`로 overflow를 숨기지 않는다. 문장 축약 → 정보 통합 → 장표 재설계 순서로 해결한다.
- 한국어는 `AppleGothic` 또는 실제 변환 환경에 설치된 일반 고딕체, 코드는 `Menlo`를 사용한다.
- 한글 glyph와 글꼴 대체는 최종 전 페이지 렌더에서 확인한다.

## 5. Layout 정책

- Canvas: 16:9, 1280 × 720
- 안전 여백: 좌우 64px, 상단 40px, 하단 42px
- 기본 구조: 12-column grid, column gap 24px, section gap 32px
- 모서리는 0–4px로 제한하고, 카드식 dashboard보다 선·면·활자·간격으로 위계를 만든다.
- 그림자와 3D 효과를 쓰지 않는다.
- 같은 layout silhouette을 세 장 연속 사용하지 않는다.
- 텍스트 상자와 구분선·색상 면의 경계 사이에는 모든 방향으로 최소 12px의 안전 간격을 둔다.
- 표와 단계 목록의 행 높이는 가장 긴 셀의 명시적 개행 수와 글자 크기에 맞춰 가변적으로 계산한다. 서로 다른 분량을 하나의 고정 행 높이에 억지로 맞추지 않는다.
- 두 줄 이상인 텍스트는 작성 코드에 `\n`을 명시하고 의미 단위에서 개행한다. 렌더러의 자동 줄바꿈을 레이아웃 수단으로 사용하지 않는다.

주요 archetype:

1. 최소 표지
2. Dark section divider
3. 대형 명제
4. 좌우 분류 비교
5. 세로형 `01–05` 단계 목록
6. Timeline·ladder·cost staircase
7. 서비스 개선 사이클
8. Matrix·trade-off map
9. Trace anatomy·schema specimen
10. Input–process–output–evaluation swimlane
11. 실제 UI 확대와 번호 annotation
12. Terminal command와 expected signal
13. Failure–recovery map
14. Application checkpoint와 worksheet

## 6. 단계·흐름 도식

- 3–5단계를 기본 범위로 하고 각 단계명은 2–6어절로 제한한다.
- 실제 시간·의존 순서가 있을 때만 화살표를 사용한다.
- 동일 위계의 모든 단계는 같은 색으로 표현한다.
- 현재 학습 위치를 보여줄 때만 하나의 단계를 파랑으로 표시한다.
- 순환 구조는 운영 결과가 다음 기획과 개선으로 다시 이어지는 서비스 개선 사이클로 그리며, 마지막 노드를 임의로 강조하지 않는다.
- 긴 단계명은 가로 한 줄로 이어 붙이지 않고 번호와 명시적 개행으로 읽기 순서를 만든다.
- 단계명·설명·코드처럼 두 줄 이상을 의도한 텍스트는 작성 데이터에 `\n`을 넣어 의미 단위를 고정한다.

## 7. 주차 로드맵 모듈

매주 표지 직후에는 동일한 정보 순서로 학기 전체와 현재 주차를 연결한다.

- 16주 전체는 대면 수업 없이 온라인으로 운영하고, 별도 표기가 없는 정규 주차는 `실시간 온라인`으로 표기한다.
- 4주차와 6주차는 공휴일에 따른 녹화영상 대체, 8주차는 실시간 수업 없는 온라인 제출·평가, 16주차는 실시간 온라인 프로젝트 발표라는 운영 차이를 명확히 구분한다.

1. 현재 주차의 날짜·학습 질문·완료 증거
2. 날짜와 수업 방식을 포함한 16주 전체 일정
3. 문제 정의부터 결과 발표까지의 포트폴리오 누적 경로
4. 해당 주차의 제출·수업 방식 변경·다음 이정표

- `currentWeek`, 날짜, 주제와 완료 증거를 데이터로 관리하고 슬라이드에 직접 고정하지 않는다.
- 현재 주차와 현재 구간만 파랑으로 표시한다. 지난 주차·예정 주차·제출 주차·마지막 주차라는 이유만으로 색을 바꾸지 않는다.
- 8주차는 `중간고사·실시간 수업 없음 · 기말 프로젝트 기획서 온라인 제출·평가`, 16주차는 `실시간 온라인 · 기말 프로젝트 결과 발표`로 표기한다.
- 2026년 9월 25일 추석과 10월 9일 한글날은 `정규 실시간 온라인 강의 대신 녹화 강의영상 업로드`라고 표기하고, 학습 범위·실습·산출물의 연결을 유지한다.
- 발표자 노트의 현재 주차·완료 증거·다음 이정표도 화면과 함께 갱신한다.

## 8. 근거와 개인정보

- 모든 장표의 발표자 노트에 `[Sources] ... [/Sources]` 블록을 둔다.
- 외부 주장·이미지는 공식 문서나 원문 논문을 우선한다.
- 저장소 내부 근거는 portable `repo:` 경로로 기록한다.
- 강의의 표지·본문·실습 서비스는 특정 대학을 대상으로 브랜딩하지 않는다. 수강 대상은 `대학생·대학원생 대상 통합 LLMOps 강좌`로 통일한다. 사용자 요청에 따라 과제 제출 경로를 구분하는 안내에서만 학교명을 사용한다: 아주대AI대학원생은 온라인 LMS, 군산대·창원대 학생은 교수자 안내 이메일.
- 공개 승인을 받은 역할명 `무신사 Core AI PM × AI 대학원 겸임교수`는 사용할 수 있다. 그 밖의 개인 연락처, 내부 조직명, 내부 프로젝트·지표, API key, 로컬 절대경로는 넣지 않는다.
- fingerprint는 동일 입력 확인용 식별자일 뿐 익명화가 아니므로, 민감 원문 자체를 실습에 사용하지 않는다.

## 9. 빌드와 QA Gate

1. 슬라이드 수 60–80장
2. 최종본의 모든 슬라이드를 PNG로 렌더하고, 동일한 판독 크기에서 1장씩 전수 검수한 기록 확보. 몽타주는 전체 흐름 확인용이며 개별 장표 검수를 대신하지 않음
3. overflow·의도치 않은 겹침 0건
4. 14pt 미만 visible text 0건
5. 금지 색상과 주황색 `#FF5A36` 0건
6. 제목 문장형 종결어미·마침표 0건
7. 의도하지 않은 두 줄 제목 0건
8. 동일·유사 제목과 동일 본문 반복 0건
9. 동일 layout 3장 연속 0건
10. 위치만으로 파랑 강조된 요소 0건
11. notes 수 = slide 수, 모든 notes에 `[Sources]`
12. `/Users/`, API key, 개인정보, 승인되지 않은 내부 회사 정보 0건
13. 실제 화면 crop, 한글 glyph, 글꼴 대체 전 페이지 확인
14. 제출 경로 안내 외 특정 대학 대상 브랜딩·학교 로고·학교별 교과목 코드 0건
15. 약어 첫 등장에 한글 용어와 영어 전체 이름 병기
16. 영문 단어와 한글 어절의 의도하지 않은 중간 줄바꿈 0건
17. 현재 주차·날짜·수업 방식·발표자 노트의 불일치 0건
17. 전체 온라인 운영, 공휴일 녹화영상 대체, 8주차 온라인 제출·평가, 16주차 실시간 온라인 발표의 누락 0건
18. 텍스트와 구분선·색상 면 경계 사이 12px 미만 간격 0건
19. 고정 행 높이로 인한 과도한 여백·잘림 0건, 두 줄 이상 텍스트의 명시적 개행 누락 0건
20. 실습 장표의 저장소 루트·파일 상대 경로·VS Code 작업명·서버 주소·종료 방법 누락 0건
21. 응용 프로그래밍 인터페이스 경로는 구현과 같은 전체 경로 사용, `/traces`·`/stats` 같은 임의 축약 0건
22. 실행 화면의 추적 식별자·응답 지연·토큰은 `실행 예시`로 표시하고 모든 환경의 고정 기대값처럼 서술한 문구 0건
23. Ollama 모델 태그·Thinking 요청값·컨텍스트·출력 상한·유지 시간은 코드·환경 파일·노트북·PPT·PDF에서 동일
24. 전체 화면 캡처 안의 작은 글씨는 별도 확대·보조 레이블로 보완하고 캡처 내부 판독성까지 육안 검사

실습 구간은 학생이 PDF만 보고도 다음 순서를 재현할 수 있어야 한다.

1. 저장소 루트 열기와 Python 인터프리터 선택
2. 환경 준비와 자동 테스트
3. 서버 시작과 `GET /health` 확인
4. 필수 Demo 기준선 실행
5. 선택 Ollama 설정·실행
6. 실행 추적·집계·지표 비교
7. 오류 복구와 서버 종료
