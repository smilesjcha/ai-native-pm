# 부서장 관점 검수표

| 검수 항목 | 질문 | 오류 초안 판정 | 고치는 방향 |
| --- | --- | --- | --- |
| 근거 | 제공된 사실로 뒷받침되는가? | 아니오 | 4개 시스템, 약 30분, 반복 문의만 사실로 쓴다. |
| 단정 | 확인 전 원인·효과를 확정했는가? | 예 | 통합 가능성·비용·효과는 [확인 필요] 또는 [가정]으로 표시한다. |
| 누락 | 배경·목표·대상·일정·리스크가 있는가? | 일부 누락 | 3단계 실행과 4주 일정, 리스크를 추가한다. |
| 중복 | 같은 문제를 반복해 문장이 늘어났는가? | 예 | 문제 설명을 한 문장으로 통합한다. |
| 실행 주체 | 누가 언제 무엇을 하는가? | 불명확 | 운영 담당자, 인사·운영 담당자, 운영 책임자의 역할을 나눈다. |
| KPI | 무엇을 어떤 기준으로 측정하는가? | 불명확 | 입력 시간과 누락 문의를 1주차 기준값부터 기록한다. |
| 결정 요청 | 승인권자가 결정할 항목이 한 문장인가? | 아니오 | 4주 시험과 참여자·대상 선정을 승인 요청한다. |

## 수정 요청 프롬프트

```text
아래 초안을 부서장 관점에서 고쳐 주세요. 제공된 사실만 사실로 쓰고, 근거 없는 단정은 [가정] 또는 [확인 필요]로 바꾸세요. 배경, 문제, 목표, 3단계 실행, 4주 일정, KPI 측정, 리스크, 승인 요청을 포함하되 600자 이내로 작성하세요. 책임 주체와 마지막 결정 요청을 명확히 하세요.
```
