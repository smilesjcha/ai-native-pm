# Week 01 — LLM 서비스 운영의 기본

## 강의 정의

- 핵심 문장: 수강생은 대규모 언어 모델(Large Language Model, LLM)을 한 번 호출하는 사람에서 응답을 기록·평가·재현·개선하는 운영자로 전환한다.
- 기본 운영: 대면 수업 없는 180분 실시간 온라인 워크숍(개념·대화 120분, 환경·실습 47분, 휴식 20분, 회고 3분).
- 압축 운영: 100분 실시간 온라인 핵심 경로.
- 실습 서비스: TRACE/01, 필수 결정론적 Demo 프로바이더와 선택 Ollama `qwen3:4b-instruct` 프로바이더.
- 완료 조건: 실행 가능한 서비스, 같은 입력의 실행 추적(trace) 2건 이상, 단일 변수 비교, 다음 개선 판단 2문장.

## 이번 학기 프로젝트 운영

- 평가 구조: 중간고사와 실시간 수업 없이 8주차에 기말 프로젝트 기획서 0.1을 온라인으로 별도 제출·평가.
- 제출 패키지: 16주 로드맵 HTML, 2페이지 제안서 HTML, 제품 요구사항 문서(Product Requirements Document, PRD) HTML, 발표용 PowerPoint 요약.
- 누적 방식: 1–7주차의 문제 정의, 실행 추적, 데이터 검토, 기술 선택, 평가 기준, 버전 기록을 하나의 기획서와 포트폴리오로 통합.
- 질의응답 방식: 교수 질문 → 학생 결정 → 근거 보강 → 수정 이력 → 다음 질문의 반복.
- 8주차 제출의 핵심: 문제·사용자, 대표 입력, 성공·금지 조건, 평가 방법, 시스템 범위, 운영 위험, 실행 계획, 포트폴리오 검증 자료.
- 기말 프로젝트의 핵심: 제출한 기획서의 주장과 가설을 서비스, 실행 기록, 비교 평가, 개선 이력으로 검증.

- 16주 전체는 대면 수업 없이 온라인으로 운영하며, 별도 표기가 없는 정규 주차는 정해진 시간의 실시간 온라인 강의다.
- 오늘은 **1주차 실시간 온라인 수업**이다. 16주 전체 일정을 먼저 공유한 뒤, 호출 결과를 비교 가능한 실행 추적으로 바꾸는 첫 베이스라인을 만든다.
- 매주 강의안 초반에는 동일한 16주 로드맵을 배치하고 해당 주차만 파란색으로 표시한다. 과거·미래 주차는 위계를 낮추되 내용과 일정은 유지한다.
- 4주차 **2026년 9월 25일 금요일·추석**과 6주차 **2026년 10월 9일 금요일·한글날**은 휴강이 아니다. 정규 실시간 온라인 강의 대신 녹화 강의영상을 업로드하며 학습 범위·실습·산출물은 그대로 운영한다.
- 8주차는 중간고사와 실시간 온라인 강의 없이 기말 프로젝트 기획서 0.1을 온라인으로 별도 제출하고 제출물 평가를 진행한다.
- 16주차는 기말 프로젝트 발표와 질의응답을 실시간 온라인으로 진행한다.
- 실시간 접속 정보, 영상 위치·시청 기한, 제출 시각과 세부 운영은 학습관리시스템(Learning Management System, LMS) 공지를 따른다.

## 이 과목의 서비스 개선 단계

이 강의의 5단계는 업계의 유일한 표준이 아니다. 2025년 2학기 자료의 구조를 16주 산출물과 운영 기록에 맞춰 재정리한 대규모 언어 모델 서비스 개선 단계다.

1. 기획·데이터
2. 프롬프트·맥락
3. 실행·배포
4. 평가·관찰
5. 개선·버전

훈련(Training), 평가(Evaluation), 배포(Deployment), 유지관리(Maintenance), 폐기(Retirement)는 모델 또는 전체 인공지능 시스템의 생성부터 종료까지를 설명하는 또 다른 관점이다. 이 과목의 개선 단계와 경쟁하는 오답이 아니라 관리 대상과 목적이 다른 분류다. 미세조정은 여러 변경 방법 중 하나이며, 폐기는 서비스 개선 5단계와 별도로 판단하는 운영 기준이다.

이 과목은 성공·금지 조건, 사용자·업무·데이터·권한, 변경 대상·이유, 동일 입력·평가 기준을 모든 개선 결과를 비교하는 공통 기준으로 사용한다.

## 용어 표기 원칙

- 축약어를 처음 제시할 때 한글 의미와 영문 풀네임을 함께 쓴다.
- 대규모 언어 모델 운영(Large Language Model Operations, LLMOps), 기계학습 운영(Machine Learning Operations, MLOps), 개발·운영(Development and Operations, DevOps)을 구분한다.
- 검색 증강 생성(Retrieval-Augmented Generation, RAG), 지도 미세조정(Supervised Fine-Tuning, SFT), 인간 피드백 기반 강화학습(Reinforcement Learning from Human Feedback, RLHF), 직접 선호 최적화(Direct Preference Optimization, DPO), 저랭크 적응(Low-Rank Adaptation, LoRA)을 처음 노출할 때 풀어 쓴다.
- 응용 프로그래밍 인터페이스(Application Programming Interface, API), 그래픽 처리 장치(Graphics Processing Unit, GPU), 개인식별정보(Personally Identifiable Information, PII)도 같은 원칙을 적용한다.

## 학습성과

1. 인공지능, 딥러닝, 트랜스포머(Transformer), 대규모 언어 모델의 발전 과정과 새로 생긴 운영 과제를 설명한다.
2. 모델 성능과 서비스 신뢰성의 차이를 사용자·맥락·성공 기준·제약사항으로 설명한다.
3. 프롬프트, 검색 증강 생성, 도구 호출, 모델 라우팅, 지도 미세조정, 선호 학습, 저랭크 적응의 적용 범위와 비용·롤백 난이도를 구분한다.
4. 개발·운영, 기계학습 운영, 대규모 언어 모델 운영에서 관리 항목이 어떻게 늘어나는지 설명한다.
5. 품질·지연시간·비용·안전성·재현성을 공통 평가 기준으로 사용한다.
6. 서비스 개선 사이클을 자신의 기말 프로젝트 기획서와 16주 산출물에 연결한다.
7. Python 3.11.14 환경에서 응용 프로그래밍 인터페이스를 실행하고 최소 실행 추적 스키마를 확인한다.
8. 한 번에 변수 하나만 바꾼 베이스라인·변경안 비교로 다음 버전 가설을 제시한다.

## 80장 슬라이드 콘티

### A. 학기 일정과 기획서 제출 — 1–7

#### 1. LLM 서비스 운영의 기본
- 화면: 검정 바탕의 대형 제목과 1주차 오리엔테이션·라이프사이클·실행 추적 표기.
- 핵심: 모델 호출을 기록·비교·개선 가능한 운영 단위로 바꾸는 첫 수업.

#### 2. 1주차의 위치
- 화면: 현재 1주차의 날짜·질문·완료 증거와 16주 포트폴리오 6구간 레일. 현재 구간만 파란색으로 표시.
- 핵심: 오늘 만든 첫 트레이스 베이스라인이 8주차 기획서와 기말 프로젝트 검증의 출발점임을 먼저 확인.

#### 3. 16주 수업 일정
- 화면: 1–8주차와 9–16주차를 좌우로 나눈 일정표. 각 주차의 날짜·진행 방식·핵심 주제를 14pt 이상으로 표기.
- 핵심: 모든 주차의 온라인 운영을 전제로 1주차 실습 베이스라인, 8주차 온라인 제출·평가, 16주차 실시간 온라인 프로젝트 발표까지의 누적 경로.

#### 4. 16주 포트폴리오 로드맵
- 화면: 문제·출력 기준, 데이터·근거, 기술·기획, 서비스·관찰, 평가·운영, 통합·발표의 여섯 구간 로드맵.
- 핵심: 매주의 코드·기록·질문·수정이 하나의 포트폴리오로 누적.

#### 5. 기획서 제출 패키지
- 화면: 로드맵 HTML, 2페이지 제안서 HTML, 제품 요구사항 문서 HTML의 표지형 미리보기와 파일 경로, PowerPoint 요약 제출 기준.
- 핵심: 중간고사와 실시간 수업 없이 8주차에 구현 범위와 평가 기준을 담은 기말 프로젝트 기획서 0.1을 온라인으로 제출·평가.

#### 6. 교수 설계 리뷰와 수정 기록
- 화면: 교수 질문, 학생 결정, 근거 보강, 수정 이력, 다음 질문을 번호와 개행으로 배치한 반복 구조.
- 핵심: 정답 확인이 아니라 설계 선택과 근거를 선명하게 만들고 변경 이유를 포트폴리오에 남기는 과정.

#### 7. 공휴일 주차의 녹화 강의

## 현업 관점의 교수자 노트

- 훈련·평가·배포·유지관리·폐기를 틀린 답으로 처리하지 않는다. 먼저 관리 대상, 목적, 반복 여부, 종료 조건을 확인한다.
- 이 과목의 5단계를 업계의 단일 표준이라고 말하지 않는다. 16주 산출물을 연결하기 위한 수업용 서비스 개선 단계로 범위를 명확히 한다.
- 모든 정규 수업은 대면 없이 실시간 온라인으로 운영한다. 4·6주차는 녹화영상으로 대체하고 16주차 프로젝트 발표는 실시간 온라인으로 진행한다.
- 별도의 중간고사는 시행하지 않는다. 8주차에는 실시간 수업 없이 기말 프로젝트 기획서 0.1을 온라인으로 제출·평가하며, 이 제출본은 1–7주차의 증거를 통합해 이후 구현 범위를 합의하는 이정표다.
- 교수는 정답을 대신 정하지 않고 질문으로 설계의 빈칸과 근거 부족을 드러낸다.
- 학생은 교수 질문을 그대로 답안에 붙이지 않고 자신의 결정, 근거, 변경 내용을 수정 이력으로 남긴다.
- 설치에서 막히면 짝 프로그래밍 또는 결정론적 데모 프로바이더로 전환해 환경 복구가 유일한 성과가 되지 않게 한다.
- Ollama 수업 모델은 `qwen3:4b-instruct`로 고정한다. `qwen3:4b` 별칭은 현재 Thinking 전용 모델과 같은 ID이며 `--hidethinking`은 추론 표시만 숨긴다는 차이를 설명한다.
- 최신·가장 큰 모델보다 같은 입력·버전·평가 기준을 고정하는 습관을 먼저 만든다.
- 평균 지연시간만 제시하면 p50·p95와 개별 트레이스를 함께 묻고, 결과만 제시하면 프롬프트·모델·설정 버전을 묻는다.
- 실제 고객 원문을 사용하지 않는다. 입력 해시는 익명화가 아니라 동일 입력 비교용 식별자다.
- 토큰 수는 교육용 추정치임을 명시하고 실제 과금 판단에는 모델 토크나이저 또는 프로바이더 사용량을 사용한다.
- 결과가 좋아졌다는 주장에는 대표 실패, 다른 평가 기준의 성능 저하, 다음 변경 가설을 함께 요구한다.
- 파랑은 현재 초점, 변경 변수, 실제 운영 기록처럼 의미가 있을 때만 사용한다. 마지막 단계나 마지막 장이라는 이유만으로 강조하지 않는다.
