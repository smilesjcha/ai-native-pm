## Step 1: 아이디어 → PRD 재료 준비 (15분)

> **19:30 ~ 19:45**

### 목표

아래 **5가지 항목**을 채우는 것이 이 단계의 전부입니다.

### 작성 템플릿

메모장에 아래 내용을 복사한 뒤, 빈칸을 채워주세요.

```
[내 서비스 기획안]

1. 서비스명: 
2. 타겟 유저: 
3. 핵심 문제: 
4. AI 활용점: 
5. 성공 기준: 
```

### 🟢 공통 트랙 예시 (오늘의 점심 메이트)

```
[내 서비스 기획안]

1. 서비스명: 오늘의 점심 메이트
2. 타겟 유저: 매일 점심 메뉴 고민이 많은 강남/판교 직장인
3. 핵심 문제: 매일 "뭐 먹지?" 고민에 평균 12분을 낭비하고, 
   결국 같은 메뉴만 반복하게 됨
4. AI 활용점: 사용자의 기분, 날씨, 예산을 입력받아 
   AI가 개인 맞춤 점심 메뉴 3개를 추천
5. 성공 기준: AI 추천 메뉴 수락률 60% 이상
```

### 항목별 작성 가이드

| # | 항목 | 잘 쓰는 Tip | 흔한 실수 |
|---|------|-----------|----------|
| 1 | **서비스명** | 한눈에 뭐 하는 건지 알 수 있게 | "스마트 플랫폼" 같은 모호한 이름 |
| 2 | **타겟 유저** | 구체적으로! "누구"인지 상상할 수 있게 | "모든 사람" (타겟이 없는 것과 같음) |
| 3 | **핵심 문제** | **사용자 관점**으로 작성 (기술 관점 X) | "AI 모델 정확도가 낮다" (기술 관점) |
| 4 | **AI 활용점** | AI가 없으면 어려운 부분을 명시 | "UI를 예쁘게 만든다" (AI 불필요) |
| 5 | **성공 기준** | 숫자로 측정 가능하게 | "사용자가 만족한다" (측정 불가) |

### 짝꿍 피드백 (3분)

5개 항목을 다 채웠으면:
1. 옆 사람에게 보여주기
2. 한 가지 질문: **"이 서비스를 당장 쓸 것 같나요?"**
3. "네" → 좋은 신호! "글쎄" → 핵심 문제가 공감되는지 다시 점검

## Step 2: Manyfast.io로 PRD 초안 생성 (15분)

> **19:45 ~ 20:00**

### 진행 순서

**1. Manyfast.io에서 새 프로젝트 생성**

**2. Step 1에서 작성한 5개 항목을 입력**
- 서비스명 → 프로젝트 이름
- 타겟 유저, 핵심 문제, AI 활용점, 성공 기준 → 요구사항에 입력

**3. PRD 생성 실행**
- "PRD 생성" 또는 유사 버튼 클릭
- 생성까지 30초~1분 소요

**4. 생성된 PRD 리뷰**
- 전체를 꼼꼼히 읽을 필요 없음
- 아래 **3가지 검수 포인트**만 확인

### PRD 검수 포인트 ✅

| # | 체크 항목 | 확인 방법 |
|---|----------|----------|
| 1 | **문제 정의가 구체적인가?** | "~한 문제가 있다"가 아니라 "N명이 X분을 낭비한다" 같은 수치가 있는지 |
| 2 | **In Scope / Out of Scope가 명확한가?** | "이건 만든다 / 이건 안 만든다"가 구분되어 있는지 |
| 3 | **성공 지표에 숫자가 있는가?** | "사용자 만족" 같은 모호한 표현이 아니라 "수락률 60%" 같은 수치가 있는지 |

> 💡 **수정이 필요하면?** Manyfast에서 직접 편집하거나, AI에게 "문제 정의 부분에 구체적인 수치를 추가해줘"라고 재요청

### 핵심 기능 부분 복사 & 저장 🔑

PRD 전체가 아니라, **아래 부분만** 복사해서 메모장에 저장하세요:

```
[복사할 부분]
1. 서비스 한 줄 설명
2. 핵심 기능 목록 (3~5개)
3. 타겟 유저 설명
```

> ⚠️ **비용 주의**: 다음 단계에서 Claude에 붙여넣을 때, PRD 전체를 넣으면 토큰 비용이 높아집니다. **3줄 요약본**을 사용하세요!

## Step 3: Claude Code로 프로토타입 제작 (15분)

> **20:00 ~ 20:15**

### 목표

저장한 PRD 핵심 내용을 Claude에 붙여넣기 → HTML 프로토타입 생성 → 브라우저로 확인

### 프롬프트 템플릿 (복사해서 사용하세요)

```
아래 PRD를 기반으로 모바일 웹 UI 프로토타입을 HTML 단일 파일로 만들어줘.

[서비스명]: (여기에 서비스명)
[핵심 기능]:
- (기능 1)
- (기능 2)  
- (기능 3)
[타겟 유저]: (여기에 타겟 유저)

조건:
- 단일 HTML 파일 (CSS, JS 모두 포함)
- 모바일 반응형 (max-width: 420px 기준)
- 한국어 UI
- AI 응답은 미리 정의된 목록에서 랜덤 선택 (실제 API 연동 불필요)
- 깔끔하고 현대적인 디자인
- 메인 화면 + 결과 화면 구성
- 실제 버튼 동작 포함
```

### 🟢 공통 트랙 프롬프트 예시

```
아래 PRD를 기반으로 모바일 웹 UI 프로토타입을 HTML 단일 파일로 만들어줘.

[서비스명]: 오늘의 점심 메이트
[핵심 기능]:
- 오늘 기분 선택 (5가지: 기분좋음, 피곤, 매운거, 가볍게, 특별한날)
- 예산 선택 (8천원 이하, 8천~1.5만, 1.5만 이상)
- AI가 기분+예산 기반으로 점심 메뉴 3개 추천 (메뉴명, 식당명, 거리, 가격, 추천 이유)
[타겟 유저]: 매일 점심 메뉴 고민이 많은 직장인

조건:
- 단일 HTML 파일 (CSS, JS 모두 포함)
- 모바일 반응형 (max-width: 420px 기준)
- 한국어 UI
- AI 응답은 미리 정의된 메뉴 목록에서 매칭 (실제 API 불필요)
- 깔끔하고 현대적인 디자인, 주황색 포인트 컬러
- 기분 선택 → 예산 선택 → 로딩 → 추천 결과 화면 흐름
- 각 추천 결과에 "여기로 갈래요" 수락 버튼 포함
```

### 사용 방법 (Claude.ai 웹 기준)

1. claude.ai 대화창에 위 프롬프트 붙여넣기
2. Enter (전송)
3. Claude가 HTML 코드를 생성 (1~2분 소요)
4. 생성된 코드를 전체 복사 (Copy 버튼 클릭)
5. 메모장(또는 VSCode)에 붙여넣기
6. `prototype.html`로 저장
7. 브라우저에서 파일 열기 (더블클릭 또는 드래그)

### 사용 방법 (Claude Code 터미널 기준)

1. 터미널에서 작업 폴더로 이동: `cd ~/Desktop/fastcampus-workshop`
2. `claude` 입력하여 Claude Code 실행
3. 위 프롬프트 입력
4. Claude가 자동으로 `prototype.html` 파일 생성
5. 브라우저에서 확인: `open prototype.html`

### 결과물이 아쉬울 때 — 수정 프롬프트

| 상황 | 프롬프트 |
|------|---------|
| 디자인이 밋밋 | "디자인을 더 세련되게 수정해줘. 그림자, 그라디언트, 애니메이션 추가" |
| 기능이 안 동작 | "X 버튼 클릭 시 Y 화면으로 이동하도록 수정해줘" |
| 화면이 부족 | "결과 화면 아래에 '다시 추천받기' 버튼을 추가해줘" |
| 데이터가 적음 | "추천 메뉴 데이터를 카테고리별 3개씩 총 15개로 늘려줘" |

### 트러블슈팅

| 문제 | 원인 | 해결 |
|------|------|------|
| HTML이 안 열림 | 파일 확장자 문제 | `.html`로 끝나는지 확인, `.txt` 아닌지 체크 |
| 화면이 하얗게 나옴 | JS 오류 | Claude에게 "콘솔 오류를 확인하고 수정해줘" 요청 |
| 디자인이 깨짐 | CSS 문제 | "모바일 화면에 맞게 CSS를 수정해줘" 요청 |
| Claude 응답이 끊김 | 토큰 제한 | "이어서 작성해줘" 입력 또는 "HTML 파일을 완성해줘" |

## 📎 부록: 하네스 엔지니어링 (Harness Engineering) 소개

> 실습 시작 전 관심 있는 분들에게 간단히 안내

이 레포지토리(`ai-native-pm`)는 Claude Code가 PM 문서를 생성할 때 참조하는 **컨텍스트 패키지**입니다.

```
ai-native-pm/
├── CLAUDE.md          ← Claude가 따라야 할 규칙 (네이밍, 구조)
├── context/           ← 도메인 지식 (AI 입력 자료)
├── docs/templates/    ← PRD 템플릿
├── docs/evaluation/   ← 3관점 평가 기준
└── projects/          ← 프로젝트별 산출물
```

**핵심 아이디어**: CLAUDE.md에 규칙을 정의하면, Claude Code가 이 규칙을 자동으로 따릅니다.
- 문서 구조를 표준화하면 AI의 출력 품질이 올라감
- 평가 기준을 정의하면 AI가 자가 점검 가능
- 도메인 지식을 축적하면 AI가 더 정확한 문서를 생성

> 관심 있으신 분은 GitHub 레포를 공유해드리겠습니다.
