## 1. 배경 (Background)

AI-Native PM은 Claude Desktop / Codex Desktop으로 로컬에서 Markdown 기반 PRD·2-Pager·Roadmap·Context·Policy 문서를 매우 빠르게 생성할 수 있게 되었다. 하지만 그 문서를 사람에게 공유하고 피드백을 받는 과정은 여전히 Confluence 댓글, GitHub PR Review, Slack 쓰레드, 회의 노트 등에 흩어져 있어, PM이 다시 MD에 반영하는 데 큰 수작업 비용이 든다. **"AI가 빠르게 쓰는 만큼, 사람의 피드백도 같은 속도로 다시 AI에게 흘려보내는 루프"** 가 필요하다.

---

## 2. 문제 (Problem)

| 문제 | 영향 (정량) | 근거 |
|------|-----------|------|
| 피드백이 4개 이상 채널(Confluence/GitHub/Slack/회의)에 흩어져 PM이 MD에 통합 정리하는 데 평균 1~2시간 소요 | PM 1인 주당 5~10시간 손실 추정 | 사내 PM 인터뷰 (정성, n=동료 PM) |
| 피드백 반영 이력이 코멘트와 분리되어, "누가 무엇을 언제 말했고 어떻게 반영됐는지" 추적 불가 | 리뷰 라운드 2회차 이상에서 동일 피드백 재발생률 30%+ | Confluence 댓글 vs 최신본 비교 (정성) |
| AI가 빠르게 쓴 초안에 비해, **피드백 → 개선안 도출**은 여전히 사람 손에 머물러 있음 | 1차 초안 작성 30분 vs 피드백 반영본 작성 3시간+ | 본인 작성 시간 측정 |

---

## 3. 솔루션 (Solution)

로컬에 있는 Markdown 파일을 웹에서 GitHub/Confluence처럼 렌더링하고, **문서/섹션/라인 단위 댓글**을 받은 뒤 "피드백 저장" 버튼 한 번으로 다음 두 종류 산출물을 동시에 생성한다:

1. **원본 + 피드백 히스토리 MD** — 원본 본문 아래에 날짜·작성자·카테고리 태그가 붙은 피드백 이력이 누적되는 Living Document
2. **AI 개선 요약 MD** — Claude/Codex CLI가 6개 카테고리(정책/컨텍스트/문제/해결점/기능/화면) × 2계층(High-Level/Low-Level)으로 피드백을 분류하고, **카테고리별 개선안 3개**를 자동 추천

이후 PM은 Claude Desktop / Codex Desktop으로 돌아가 그 두 MD를 그대로 입력으로 사용하여 다음 리비전을 만든다.

### AS-IS → TO-BE

| 항목 | 현재 (AS-IS) | 목표 (TO-BE) |
|------|-------------|-------------|
| 피드백 수집 | Confluence / GitHub / Slack 분산 | 웹 한 화면에서 카테고리 태그된 댓글로 일원화 |
| 피드백 정리 | PM이 수작업으로 채널별 취합 | "저장" 클릭 시 자동으로 두 종류 MD 산출 |
| 개선안 도출 | PM 머리속 → 다음 초안 작성 | AI가 카테고리별 3개 대안 사전 추천 |
| 반영도 추적 | 불가능 | 주간/월간 점수로 시각화 (v2) |

## 6. 리스크 (Risks)

| 리스크 | 영향 | 대응 방안 |
|--------|------|----------|
| MD 호환성 깨짐 (피드백 메타가 일반 MD 뷰어에서 노이즈가 됨) | GitHub/VS Code 등에서 가독성 저하 | 메타는 `<details>` 접이식 + HTML 주석으로 격리, 표준 마크다운 호환 유지 |
| AI 카테고리 분류 오류 | 잘못된 개선안 추천 → 신뢰도 하락 | PM이 수동 재분류 가능한 UI 제공, 학습 피드백 루프 (v2) |
| 로컬 의존성 (Claude/Codex CLI 미설치 환경) | 사용 불가 | MVP는 본인 사용 전제, 외부 공개 전 CLI 설치 가이드 + 폴백 API 옵션 |
| 본 프로젝트가 무한 기능 확장의 함정에 빠짐 (자체가 Living Doc + AI Tool 융합이라 범위가 넓음) | 릴리즈 지연 | MVP 스코프를 "MD 뷰 + 댓글 + 2종 저장" 3가지로 엄격 고정, 점수 대시보드는 v2로 명시 분리 |
