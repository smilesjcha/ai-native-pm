## §2. Executive Summary

AI-Native PM이 Claude Desktop / Codex Desktop으로 매우 빠르게 작성한 Markdown 문서(PRD, 2-Pager, Roadmap, Context, Policy)에 대해, **웹에서 GitHub/Confluence처럼 렌더링 + 댓글 피드백을 받고**, "저장" 한 번으로 **(1) 원본+피드백 이력 MD** 와 **(2) AI가 6카테고리×2계층으로 분류하고 카테고리별 개선안 3개를 추천한 개선 요약 MD** 두 종류를 동시에 산출하는 Local-first 웹 협업 도구를 만든다. MVP 4주 안에 "MD 뷰 / 댓글 / 2종 저장" 3가지 핵심 동작을 확보하고, v2에서 주간·월간 피드백 반영도 점수와 문서별 스코어 시각화 대시보드를 더해, **AI가 쓰는 속도와 사람이 피드백을 주는 속도를 같은 루프로 묶는다.**

## §3. Problem Definition

| 문제 ID | 문제 설명 | 영향 (정량) | 근거 자료 | 해결 방향 |
|---------|----------|-----------|----------|----------|
| P1 | 피드백이 Confluence / GitHub PR / Slack / 회의 노트 4채널 이상에 흩어진다 | PM 1인 주당 5~10시간 통합 정리 비용 | 사내 PM 인터뷰 (정성) | 웹에 단일 코멘트 평면 제공 |
| P2 | "누가 / 언제 / 어떤 카테고리"의 피드백이 어떻게 반영됐는지 추적 불가 | 동일 피드백 재발생률 30%+, 리뷰 라운드 길어짐 | Confluence 댓글 vs 최신본 비교 | 원본+이력 MD 자동 생성, 카테고리 태깅 |
| P3 | AI가 빠르게 쓴 초안 vs 피드백 반영본 작성 비용 비대칭 (30분 vs 3시간+) | 1차 사이클 빠른데 2차 이후가 병목 | 본인 작성 시간 측정 | AI에 피드백+원본 통째로 입력 가능한 산출물 자동 생성 |
| P4 | 피드백 반영도를 측정할 방법이 없어, "이 PRD가 얼마나 잘 진화하고 있는가"를 객관화하기 어려움 | 리더십·EM·디자이너의 신뢰도 형성에 시간 소요 | 평가 워크플로우(docs/evaluation/) 운영 경험 | 주간/월간 반영률 점수 + 문서별 스코어 시각화 (v2) |

### AS-IS (현재 상태)

PM은 Claude Desktop / Codex Desktop으로 30분 안에 PRD 초안을 만든다. → Confluence에 올린다 → 동료가 인라인 댓글을 남긴다 → 일부는 Slack DM으로, 일부는 회의 노트로 추가 의견을 준다 → PM이 다음날 1~2시간 들여 채널별 피드백을 취합한다 → 머리속에서 정리한 뒤 Claude에게 다시 "이렇게 고쳐줘"를 자연어로 부탁한다 → Claude는 PM의 정리본만 보고 원본 피드백의 뉘앙스를 모르는 채로 수정한다.

**결국 AI는 빠른데, 사람-AI 사이의 피드백 왕복이 느리다.**

## §4. Solution Proposed

### 핵심 가설

> "만약 **로컬 MD를 웹에서 렌더링 + 댓글 받기 + 저장 한 번으로 (원본+이력 MD) + (AI 카테고리별 개선안 MD) 두 종류를 동시에 산출**하는 도구를 제공하면, **AI-Native PM의 피드백 반영 사이클 타임이 1~2일에서 1~2시간으로 단축**될 것이다."

### AS-IS → TO-BE

| 항목 | AS-IS | TO-BE |
|------|-------|-------|
| 피드백 채널 | Confluence / GitHub / Slack / 회의 | 웹 한 화면, 6카테고리 태그된 댓글 |
| 피드백 정리 | PM 수작업 1~2시간 | 저장 클릭 → 자동 2종 MD 산출 |
| 개선안 도출 | PM 머리속 → 다음 초안 작성 | AI가 카테고리별 3개 대안 사전 추천 |
| AI 재입력 | 자연어로 PM이 요약 전달 | 원본+이력 MD를 그대로 입력으로 사용 |
| 반영도 추적 | 불가능 | 주간/월간 점수 + 문서별 스코어 (v2) |

### 단계별 방향

| 단계 | 방향 | 핵심 산출물 |
|------|------|-----------|
| MVP (2026-06) | MD 뷰 + 댓글 + 2종 저장 + AI 개선안 3개 | 웹 앱 + Claude/Codex CLI 연동 + 2 종류 MD 출력 |
| v2 (2026-07) | 점수 대시보드 + 문서별 스코어 | 주간/월간 반영률, PRD/2pager/Roadmap 별 시각화 |
| v3 (이후) | 팀 단위 호스팅 + 권한 모델 | 다중 사용자, 코멘트 권한, 알림 |

## §6. Scope (In/Out/Future)

### In Scope (MVP, 2026-06)

- [ ] Local 파일시스템의 `.md` 파일 디렉토리 트리 뷰
- [ ] GitHub Flavored Markdown 렌더링 (코드/표/이미지/체크박스/Mermaid 옵션)
- [ ] 문서 단위 + 섹션(헤딩) 단위 + 라인 단위 댓글
- [ ] 6카테고리(정책/컨텍스트/문제/해결점/기능/화면) × 2계층(High/Low) 태깅
- [ ] "피드백 저장" 버튼 → (a) 원본+이력 MD (b) AI 개선 요약 MD 두 종류 동시 생성
- [ ] AI 개선 요약 MD에는 카테고리별 개선안 3개 자동 추천 (있으면 있는 대로, 없으면 AI 기반 아이디어 3개)
- [ ] Claude CLI / Codex CLI 호출 어댑터
- [ ] 산출물은 GitHub/VS Code/일반 MD 뷰어에서도 깨지지 않는 표준 마크다운 호환

### Out of Scope (MVP)

- 다중 사용자 권한 모델 (MVP는 단일 사용자 / 소규모 팀 신뢰 기반)
- 실시간 동시 편집
- 모바일 네이티브 앱
- Confluence/Jira 자동 양방향 동기화 (v3 이후)

### Future Consideration

- 주간/월간 반영도 점수 + 문서별 스코어 시각화 → **v2 (2026-07)**
- 팀 단위 호스팅 + SSO + 권한 → v3
- 피드백 학습을 통한 카테고리 분류 정확도 자동 개선 → v3
- Confluence / Jira 양방향 → v3 이후

## §8. Entry Surface & UX

### 진입점 정의

| 진입점 | 화면 | 노출 조건 | 우선순위 |
|--------|------|----------|---------|
| 앱 실행 직후 | 폴더 선택 / 최근 폴더 | 첫 실행 | P0 |
| 문서 트리 | 좌측 트리 (디렉토리 + .md 파일) | 폴더 선택 후 | P0 |
| 문서 본문 | 중앙 렌더링 영역 | 트리에서 파일 선택 | P0 |
| 코멘트 패널 | 우측 슬라이딩 패널 | 항상 토글 가능 | P0 |
| 대시보드 (v2) | 상단 탭 | v2 이후 | v2 |

### 화면 전환 흐름

1. 앱 실행 → 폴더 선택 → 문서 트리 노출
2. 문서 클릭 → 본문 렌더링 + 우측 코멘트 패널 열림
3. 섹션/라인 호버 → 코멘트 아이콘 → 6카테고리 선택 → 댓글 작성 → 저장
4. 상단 "피드백 저장" 클릭 → 확인 모달 → AI 호출 진행 표시 → 완료 알림 (두 MD 파일 경로 표시)
5. (v2) 대시보드 탭 → 주간/월간 토글 → 카테고리별·문서별 스코어 차트

### 출력 원칙

- 메시지 포맷: 코멘트는 `> 카테고리 [High/Low] · 작성자 · YYYY-MM-DD HH:mm` 헤더 + 본문
- 디자인 토큰: 6카테고리에 색상 일관성 (정책=보라, 컨텍스트=파랑, 문제=빨강, 해결점=초록, 기능=주황, 화면=하늘)
- 컴포넌트: shadcn 스타일 좌/중/우 3 패널 + 상단 액션 바

## §19. Appendix

### 카테고리 × 계층 매핑 (고정)

| 카테고리 | 계층 | 정의 |
|----------|------|------|
| 정책 (Policy) | High-Level Context | "이 제품/조직의 원칙"에 해당하는 의견 |
| 컨텍스트 (Context) | High-Level Context | "왜 이 결정이 나왔는가"에 해당하는 배경·세계관 의견 |
| 문제 (Problem) | High-Level Context | 해결하려는 문제 정의 자체에 대한 의견 |
| 해결점 (Solution) | Low-Level Spec | 솔루션 방향·접근 방식에 대한 의견 |
| 기능 (Feature) | Low-Level Spec | 구체 기능 단위에 대한 의견 |
| 화면 (Screen) | Low-Level Spec | UI/UX 화면 단위에 대한 의견 |

### 산출 MD 파일 명명 규칙

- 원본+이력: `[원본파일명]-feedback-YYYYMMDD-HHmm.md`
- AI 개선 요약: `[원본파일명]-improve-YYYYMMDD-HHmm.md`
- 두 파일은 같은 디렉토리에 저장. 원본은 절대 덮어쓰지 않는다.

### 산출 MD 내부 구조 (요약)

**원본+이력 MD**: `## 원본` 섹션 + `## 피드백 이력` 섹션 (카테고리·계층·작성자·시각·본문 테이블)

**AI 개선 요약 MD**: `## 핵심 정리` (카테고리별 1줄) + `## 개선안` (카테고리별 3개) + `## 미반영/보류` (있으면)
