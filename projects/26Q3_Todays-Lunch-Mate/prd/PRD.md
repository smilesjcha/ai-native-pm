## 1. 전략 정합성

### 회사/조직 OKR 연결
본 프로젝트는 26년 조직 OKR인 **"AI 내재화를 통한 차별화된 일상 서비스 경험 창출"**과 직접 연결된다.

| 회사 OKR | 본 프로젝트 기여 경로 |
|----------|---------------------|
| O1. AI Native 제품군 3개 출시 | 본 서비스는 그중 첫 번째 소비자향 AI 제품 |
| KR1-1. AI 제품 MAU 5만 확보 | 26Q4까지 3만 MAU 목표 (O1의 60% 기여) |
| KR1-2. AI API 통합 비용 건당 $0.01 이하 | Claude Haiku 선택으로 $0.0015/건 달성 계획 |

### 이니셔티브 간 관계
- **시너지**: 26Q2 출시 예정 '팀 커뮤니케이션 봇'과 팀 점심 기능에서 통합 가능
- **충돌 없음**: 기존 B2B SaaS 라인업과 채널/타겟이 분리됨

### 중장기 로드맵
```
26Q3: MVP 출시 (강남/판교 커버리지)        ← 본 PRD 범위
26Q4: 서울 전역 확장 + 결제 연동
27Q1: 저녁/회식 추천 확장 (시장 2x 확대)
27Q2: B2B 구독 모델 (사내 식권 통합)
```

## 2. 문제 정의

### 정량 데이터 (근거)
| 지표 | 수치 | 출처 |
|------|------|------|
| 직장인 점심 결정 평균 소요 시간 | **12분** | 사내 설문 N=247, 2026-03 |
| 동일 메뉴 반복 선택 비율 | **65%** (주 2회 이상 동일) | 사내 설문 |
| 메뉴 결정을 "피곤하다"고 응답한 비율 | **78%** | 사내 설문 |
| 타겟 지역 점심 시장 추정 | **월 약 1,800만 끼** | 강남/판교 직장인 약 30만 × 월 20일 × 3회 |

### 정성 데이터 (VOC)
- "같이 먹는 사람이 많을수록 결정이 더 어렵다" (5/7 인터뷰이)
- "망고플레이트는 맛집은 많지만 '지금 내 기분에 맞는'이 없다" (4/7)
- "예산을 말하기 민망해서 결국 비싼 곳 따라간다" (3/7)

### 근본 원인 (Root Cause)
1. **선택지 과잉**: 1km 내 평균 140개 식당 → 인지 과부하
2. **개인화 부재**: 기존 서비스는 평점/거리 기반, 기분·예산 기반 필터 없음
3. **그룹 의사결정 마찰**: 개인 선호 취합 도구 부재

### 선행 지표 (Leading Indicator)
- 점심 시간대(11:30–13:00) 메뉴 검색 관련 키워드 증가율 → 문제 지속 여부 추적

## 4. 우선순위 정당성 (Why Now)

### 왜 지금인가
1. **AI 원가 하락**: Claude Haiku 출시로 추천 1건당 원가가 1년 전 대비 1/10 수준 ($0.015 → $0.0015)
2. **경쟁 공백**: 상위 3개 경쟁 서비스 중 기분·예산 기반 개인화는 미출시 (2026-04 기준)
3. **내부 여건**: Claude API 전사 도입 완료(26Q1), 팀 기술 스택 정렬됨

### 기회비용 (Not Doing Cost)
- 26Q4에 후속 경쟁 서비스 2개 출시 예상 → 지연 시 선점 이점 상실
- AI 내재화 첫 제품 지연 시 회사 AI OKR의 KR1-1 달성률이 약 60% → 30%로 하락

### RICE 우선순위 평가

| 항목 | Reach (분기) | Impact | Confidence | Effort (MM) | RICE Score |
|------|------|--------|-----------|--------|-----------|
| **오늘의 점심 메이트** | 30,000 | 2 (High) | 80% | 13 | **3,692** |
| (비교) 사내 툴 개선 B | 500 | 1 | 90% | 5 | 90 |
| (비교) B2B 추천 엔진 C | 5,000 | 3 | 50% | 20 | 375 |

→ RICE 기준 본 프로젝트가 약 10배 우선.

## 6. 시나리오

### Primary Scenarios (P0)

#### S1. 혼자 점심 결정 (Happy Path)
1. **트리거**: 11:30, 모바일 웹 접속
2. 오늘의 기분 선택 (든든한/깔끔한/매콤한/상관없음)
3. 예산 선택 (<1만 / 1–1.5만 / >1.5만)
4. 위치 권한 허용
5. Claude Haiku가 3개 추천 반환 (3초 이내)
6. 사용자가 1개 선택 → 지도/연락처 표시
7. (다음날) 재방문 시 이전 선택 표시, 1-탭 재추천 가능

#### S2. 팀 점심 결정 (P1)
1. 호스트가 '팀 점심' 생성 → 공유 링크
2. 팀원 2–5명이 각자 기분/예산 입력
3. AI가 **공통 최적안 3개** 추천 (각 선호도 교집합 가중치)
4. 단순 투표 또는 호스트 확정
5. 결정 결과 카톡 공유

#### S3. 위치 기반 탐색 (P1)
1. "직접 찾기" 버튼 → 지도 진입
2. 반경 500m 식당 리스트 + 필터 (카테고리/가격대/거리)
3. 식당 상세 → 연락처/메뉴

### Edge Case Scenarios

| # | 상황 | 처리 |
|---|------|------|
| E1 | 위치 권한 거부 | 지역 수동 선택 폴백 (강남역/판교역 기본) |
| E2 | 반경 500m 식당 0개 | 반경 자동 확대 (500m → 1km → 2km) |
| E3 | AI API 타임아웃 (>5s) | 캐시된 인기 메뉴 3개 제공 + "AI 지연 안내" |
| E4 | 팀 점심 입력 미완료 | 입력 완료자 기준 추천 + 미입력자 알림 |
| E5 | 사용자 기분/예산 모두 미입력 | 기본 프리셋 ("든든한 + 1–1.5만") |

### Error Scenarios

| 에러 | UI 처리 | 폴백 |
|------|--------|------|
| 네트워크 오류 | 토스트 + 재시도 버튼 | 마지막 성공 추천 표시 |
| API 응답 오류 (5xx) | 에러 페이지 | 랜덤 인기 메뉴 3개 |
| 인증 실패 (팀 세션) | 모달 | 재로그인 유도 |

## 8. UI/UX 플로우 및 컴포넌트

### 진입 → 결과 플로우 (S1 기준)

```
[랜딩] 
  └→ [기분 선택 카드] — 칩 4개 (든든/깔끔/매콤/상관없음)
       └→ [예산 선택 카드] — 라디오 3개
            └→ [위치 확인 모달] — 현재 위치 / 수동 선택
                 └→ [추천 로딩] — 3초 스켈레톤
                      └→ [추천 결과] — 카드 3개 (식당명/거리/예상가/추천 이유)
                           ├→ [선택] → [상세 + 지도]
                           └→ [재추천] → 로딩 재실행
```

### 주요 컴포넌트 (P0)

| 컴포넌트 | 상태 (States) | 인터랙션 |
|---------|------------|---------|
| MoodChip | Default / Selected / Disabled | Tap → 단일 선택, 하단 CTA 활성화 |
| BudgetRadio | Default / Selected | Tap → 다음 단계 자동 진행 |
| LocationModal | Permission Ask / Granted / Denied | 거부 시 수동 선택 드롭다운 표시 |
| RecoCard | Loading (skeleton) / Success / Empty / Error | Tap → 상세, Long-press → 피드백 |
| PrimaryButton | Default / Pressed / Loading / Disabled | 로딩 중 2클릭 방지 |
| Toast | Info / Success / Warning / Error | 3초 자동 사라짐 |

→ 기존 디자인 시스템 (Tailwind + shadcn/ui) 기반. 신규 컴포넌트는 MoodChip뿐.

### 뒤로가기·재진입 정책
- 기분/예산 입력 후 뒤로가기: 이전 선택 유지
- 결과 화면에서 뒤로가기: 예산 단계로 복귀 (기분은 유지)
- 세션 이탈 후 10분 이내 재진입: 직전 추천 결과 재표시
